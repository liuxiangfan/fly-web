# 完成质量复核（第五轮，2026-10-31）

## 总体评价

这一轮不只看门禁是否通过，而是把第五/六轮新加的能力当成**尚未被证明的新代码**逐项复核。
发现的关键问题不是缺页面或缺算法，而是**指标坐标约定、验证集定义、验证对象三者曾被「读数合理」掩盖**。

修复后，配置/导出回放、校准、传感器、统计与硬件接入的教学演示链条是可信的；仍不能宣称完美。
综合评价：**A−（约 91/100，是工程复核的启发式评分，不是测试得分）**。加分来自把复核发现的问题直接修复并加了回归；扣分来自 UI/runner 仍非完整同一调度、真机与性能边界尚未验收。

## 本轮实测确认的缺陷与修复

### P1 · SO(3) 指标的坐标约定曾写错

**现象**：`so3ErrorSplit` 文档声称输入是世界系误差，runner 却传 `q_true⁻¹ ⊗ q_est`（机体系误差），再按世界重力轴拆分。

**探针证据**：真值含 40° 偏航 + 30° 横滚，估计器绕**世界重力轴**偏 8°。旧实现输出 tilt≈3.997° / yaw≈6.923°，正确应为 tilt=0 / yaw≈8°。

**修复**：runner 改传 `q_true ⊗ q_est⁻¹`（世界系误差），`so3ErrorSplit` 明确坐标约定；补倾斜真值下「世界重力轴/机体 z/世界水平轴」三分量回归。
Golden 指纹按**有意的指标口径变更**重生成并注明，未把旧错误当成必须保持的兼容行为。

### P1 · 磁校准独立验证集与拟合集重叠

**现象**：`calibrateMagWithValidation(samples)` 内部已留出 25% 样本，但调用方又传入提前 75/25 划分的 `samples`；于是验证集实际是 `0.75 × 0.25 = 18.75%`，且与独立航向验证集 25% 有重叠。原自检 `count > 60` 恰好掩盖这一点。

**修复**：自检改用同一 `splitFitValidate` 划分样本，明确 `fit=240`、`validate=80`；`calibrateMagWithValidation` 的二次留出后的验证数应为 60，断言改为精确相等。
航向误差绝对阈值从 2° 放宽到 2° 内的合理解释并不适用——正确修复后测得 1.19°，保留 <2°，没有靠继续放宽阈值藏问题。

### P1 · 加计独立验证用硬编码的另一颗 IMU 打分

**现象**：验证固定使用 M=[1.02,…]、bias=[0.05,…]，与当前器件参数及用户拟合的标定无关；噪声也不是拟合实际使用的 0.5 s 窗口均值。任何配置都能出现「0.1615 → 0.0084」的漂亮改善，证明不了当前标定。

**修复**：抽出 `core/calib-verify.ts`，按当前交叉轴、非线性和噪声生成独立窗口均值，且与 `simulateImu` 的「另外两轴各 k」模型一致。漂移模型能给出「未见改善」，不再一律说有效。
补纯函数测试：匹配模型残差到数值精度、漂移模型残差变大并触发未见改善、含噪窗口均值有限；浏览器补当前模型有效用例（0.0010 → 0.0002 m/s²，实测为 20.2%）。

### P2 · BLE 重连可能订回错误的服务/特征

原实现自动重连重新读当前服务下拉并订第一个特征，断线期间用户改过下拉后可能订到错误对象。现在重连记住成功连接的服务 UUID 与最后订阅的特征 UUID，优先订回同一个。

### P2 · 重连测试等待了易消失的状态文案

状态条写回「已自动重连」后会立即被帧率状态覆盖。实测曾出现 opens=1、reconnects=0 的假失败；改为等待只增不减的 `plumbing().reconnects >= 1`，不再吞掉等待超时。

### P2 · 报告/文档本身也需校正

- CHANGELOG 原先把第五/六批压成一节且缺详细第六批内容，已拆为「配置/数据闭环轮」与「工程健壮性轮」，并补第五轮复核修复。
- PROJECT-STATE 的当前计数和验证口径同步，历史数字保留为当时记录。
- 量产文档的强断言改为与当前实现相符：SO(3) 是世界系小角分解；独立验证按当前器件参数评分；留一验证不能替代真实独立验证集。

## 仍不足（不要因本轮修复而淡化）

### P1 · runner 与界面仍不是完整同一条运行路径

runner 只有单组理想飞控的仿真调度，**没有**界面中的 A/B、INS、闭环、串口/BLE/回放调度、校准采集状态机。
因此「同 seed、同配置」只能在限定的仿真单组范围内理解，**不是界面结果的普适等价证明**。

**下一批建议**：
1. 先定义 `SimulationSession` 的可选能力（closedLoop、INS、A/B）和明确的事件序列；
2. 让界面的模拟路径调用它，runner/Worker 共用同一调度；
3. 加同 seed 下逐帧姿态、IMU、INS 位置与统计的 golden trace，缺能力时明确跳过并列出差异，不做隐式等价。

### P1 · 真机验证仍没有现场证据

BLE 重连还没有独立浏览器冒烟；串口重连用 mock 通过不等于真机 USB/蓝牙链路长期稳定。
 BLE 因设备离开范围/关机/GATT 失败的退避重连、用户主动断开不重连、连接互斥，需补自动化与实测。

**下一批建议**：补 BLE 假设备用例（服务/特征保留、断开恢复、手动断开、与串口互斥），再给真机验收脚本：至少 30 min、多次拔插/离开范围、记录重连次数/丢帧/内存。

### P1 · 有界统计改变了「稳态窗口」的语义

`MetricAccumulator` 超过 60000 样本后转蓄水池，蓄水池按**到达序号**抽样，样本时间分布不一定均匀；稳态窗口仍取蓄水池中时间排序后的末 40%，可能不是物理意义上的末段。
且分位数是近似，标记了 `percentileApprox`，但没有对用户说明具体误差范围。

**下一批建议**：长跑统计改为流式均值/方差/最大值 + 固定长度时间序列分桶 + 明确的末段时间窗累加器；分位数可另用 t-digest/P²，并把「精确/近似」口径写到面板，而不只放类型字段。

### P2 · 校准验证仍只证明「同一参数族的独立样本」

- 加计验证合成当前参数族，能验证模型匹配与配置漂移，**不等于真机独立姿态/温度验证**；真实模式目前回看已采样本，需明确它不具独立性。
- 磁校准留出的验证点来自同一段连续采集，虽不是同一点，但姿态相关性、温漂、时变干扰仍可能让验证偏乐观。
- 六面静止判据只筛了平均/最大角速度与模长标准差，不能替代真实静置、姿态安装误差与动态误差检查。

**下一批建议**：真实采集按时间块留出训练/验证，新增跨时段、不同姿态分布、温度区间的验证记录；将「验证残差 / 留一验证 / 真值姿态独立验证 / 真实回看」四种口径在面板上分清楚。

### P2 · Worker 与浏览器长跑还需要组合压力验收

Worker 只能等待每个种子完成再发进度，长批次无法中途取消；超时后 Worker 终止、主线程重跑，配置改变期间未测试重复启动与来源一致性。
真机、Worker 与高频采样同时开启的渲染/堆占用，尚无 10 min 级实测。

**下一批建议**：Worker 消息增加 `jobId`、`cancel`、分种子/分阶段进度与心跳，配置变更时拒绝旧结果；增加 Worker 与主线程同一输入的逐指标比对用例，以及真实 Chromium 的内存/帧率长稳报告。

### P2 · 校准应用历史/器件配置切换未形成完整生命周期

校准拟合后修改交叉轴/非线性/噪声等参数，旧标定仍可应用；独立验证能暴露一部分问题，但没有「参数变化 → 标定可能失效」的状态提示与一键重新拟合。

**下一批建议**：标定记录拟合时的模型与参数指纹；参数变化显示「标定基于旧模型」，默认提示重新采集/拟合（不要自动清空用户数据），并补切换参数、导入档案、重新拟合的组合用例。

## 后续实施顺序

1. **可信性优先**：修正有界统计稳态窗口、补 BLE 重连组合用例、真机长稳验收。
2. **统一调度**：SimulationSession + UI/runner golden trace，避免再扩展一份第二调度。
3. **独立验证真实化**：时间块/姿态/温度分层验证、校准模型指纹与失效提示。
4. **性能与维护**：Worker jobId/cancel/心跳、长跑与多源并发压力测试；继续把数据源与回放调度从 main.ts 拆出。
