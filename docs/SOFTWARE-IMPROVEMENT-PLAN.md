## 1. 范围与实施原则

只处理浏览器应用、数值内核、文件导入导出、页面交互、异步任务、自动化测试、构建、CI 和文档证据。不安排实物、固件或外接装置相关任务。会话生命周期仅以浏览器 API 的可控异步替身进行软件验证。

默认负载是单用户教学：一页同时运行五种算法、查看三维视图与曲线，按需执行回放和多种子评测。优化不以删教学能力为前提，也不引入新框架重写现有系统。

实施顺序：**正确性 → 异常安全 → 验收可信度 → 性能与体验 → 职责拆分 → 发布复核**。

- 每项先固化最小反例，再修改生产实现；修复不以提高分数或让现有测试变绿为目标。
- 测试通过只能证明覆盖的场景。文件哈希一致、成功 job、无横向滚动均不能单独证明目标完成。
- 改判据必须说明旧判据的盲区、保留的约束和新增正反例；不得放宽阈值后声称产品已优化。
- 不在采集期间修改被测构建输入。源码、构建和验收脚本各有明确身份，避免把不同版本的结果拼成一份“当前证据”。
- 提交、推送、触发远端运行及发布均先获授权；以下命令是执行说明，不构成本次操作授权。

### 证据标签

- **已复现**：上一轮已直接运行生产纯函数、受控异步夹具或生产函数故障注入；不是仅凭注释推测。
- **静态风险／待补场景**：代码路径或规范推导有明确风险，但还需对应生产入口测试。
- **已有能力**：保留并回归，不重复实现，也不扩大其证明范围。

## 3. SW-01：修复日志时间单位与时长解释

### 现状与反例

**已复现**：表头为 `t_s,gx,gy,gz,ax,ay,az`，20 行时间 `0…19`、间隔 1 秒，解析成功但播放器时长为 **0.019 秒**，正确值应是 **19 秒**。`parseImuCsv` 已识别秒列，随后仍因中位间隔大于 0.5 秒而把 `tMs` 再除以 1000。

**待补场景**：当前分类器接受 `t_us/time_us` 名称，必须验证微秒是否完整换算；不能仅凭列名“被识别”判通过。

已有 `ReplayPlayer` 单调有效时间轴、回退不重复积分和背压能力保留，不重新写第二套播放器。

### 修改位置

- [`src/core/replay.ts`](../src/core/replay.ts)：`classify`、`parseImuCsv`、`medianDelta`。
- [`src/core/replay-player.ts`](../src/core/replay-player.ts)：`load`、`durationSec`、`advanceWork`。
- [`scripts/time-contract.test.ts`](../scripts/time-contract.test.ts)：时间与积分契约。

### 具体方法

1. 时间列映射同时保存单位 `s/ms/us/unknown` 与来源 `explicit/inferred`，不要只保存一个换算系数后丢失单位来源。
2. 显式单位只做一次向毫秒的换算：秒乘 1000、毫秒不变、微秒除以 1000。对显式列禁用二次启发式重解释。
3. 启发式只处理无单位的 `t/time` 等模糊列。推断结果写入导入提示与 notes；若多种解释都合理，要求显式选择或报可操作提示，不静默替用户改单位。
4. 解析器、导入提示与播放器共用有效时长口径。回退和重复时间戳的说明应与实际“运行最大时间”规则一致，不再描述为另一套夹紧逻辑。
5. 保留坏时间列拒绝、少量重复容忍及长间隔背压；不要为了兼容低频日志而放行非有限时间值。

### 永久反例与验收

- 秒／毫秒／微秒三份等价 CSV，解析后的全部 `tMs`、播放器时长及积分轨迹一致。
- 显式秒列覆盖 0.002、1、30、300 秒间隔；至少 20 行，避免被最小帧数保护提前挡住。
- 19 秒反例必须得到末帧 `19000 ms`、`durationSec≈19`、累计积分时长约 19 秒；浮点比较使用明确容差。
- 重复时间、单次／多次／末帧回退、第一帧非零时间都不产生额外积分或双重单位转换。
- 浏览器通过正常文件导入入口验证提示、进度和结果；仅调用调试入口不能替代文件入口覆盖。

**定向命令**：`npx tsx scripts/time-contract.test.ts`，随后完整 `npm run check`。

## 4. SW-02：修复 Madgwick 玻璃盒遥测

### 现状与反例

**已复现**：单位姿态、`gyro=[0,0,1] rad/s`、`accel=[0,0,9.80665]`、磁修正关闭、`dt=0.01 s`，观测残差为 0，实际姿态只转约 0.01 rad；遥测却报告 `correction=[0,0,0.5]`、`rate=[0,0,1.5]`。这是遥测错账，不是五算法整体失效。

### 修改位置

- [`src/estimators/index.ts`](../src/estimators/index.ts)：`MadgwickEstimator.update`。
- [`src/main.ts`](../src/main.ts)：玻璃盒内部量展示。
- [`scripts/selftest.ts`](../scripts/selftest.ts)：现有遥测测试组。

### 具体方法

1. 将陀螺导数 `qDotGyro` 与融合修正导数 `qDotCorrection` 分开保存；积分仍用两者之和。
2. 遥测从修正导数单独求值。对本项目机体系→世界系、右乘机体系角速度的约定，使用更新前的单位姿态计算 `2·vec(conj(q) ⊗ qDotCorrection)`，包含标量项；若存在沿四元数径向的分量，按切空间语义处理。
3. 先用解析小例和有限差分确认符号、坐标系与系数，再定义 `rate=rawGyro+correction`。页面明确单位是 rad/s 内核量还是 °/s 显示量。
4. 本工单只修遥测，不顺带改增益、积分方法或姿态输出；修复前后真实姿态序列应保持一致。

### 永久反例与验收

- 零观测修正、非零陀螺：`correction≈0`、`rate≈gyro`。
- `beta=0` 且其他修正关闭、加计拒绝、磁修正关闭，以及三个轴分别运动。
- 水平和任意非水平**单位姿态**都成立，避免只在 `q=I` 时公式恰好正确。
- 有非零修正时，对照切空间有限差分；页面数值与内核 telemetry 一致，不再显示虚构的 28.65°/s 修正。

**定向命令**：`npm run selftest`；新增测试条数时同步机器计数声明，不删除旧测试凑数。

## 5. SW-03：完成档案导入的异常安全事务

### 现状与证据边界

**已有能力**：越界值、固定轴初态、总开关分叉等预检拒绝发生在写状态之前。

**已复现（生产函数内存故障注入）**：向校准结果渲染写入注入异常后，seed、控件和校准对象已改变，调用却失败。外层只显示失败提示，不恢复现场。

**静态风险／待真实控件确认**：`min=0,max=5,step=2,value=5` 时，离线量化预测为 5；原生 range 的合法网格是 0/2/4。预检若误放行，再切到运动学场景，会清掉 `loop.checked`；旧配置重写不足以恢复该展示状态。不得把这条规范推导写成已完成的浏览器实测。

### 修改位置

- [`src/main.ts`](../src/main.ts)：`applyArchiveChecked`、`writeArchiveState`、`commitArchiveRestore`、校准面板更新。
- [`src/core/archive-ui.ts`](../src/core/archive-ui.ts)：`archiveUiSteps`、`snapSliderValue`、`predictedArchiveReadback`。
- [`src/ui/calib-panel.ts`](../src/ui/calib-panel.ts)：纯文案／HTML 构造。
- [`scripts/archive-ui-contract.test.ts`](../scripts/archive-ui-contract.test.ts)、[`scripts/browser-smoke.mjs`](../scripts/browser-smoke.mjs)。

### 具体方法

1. 把流程明确分成 `prepare → commit`：prepare 完成 schema 检查、规范化、控件可表达性计算、校准文案构造与提交计划生成，全部不改活状态。
2. 量化不能先越过合法网格再强行夹到 `max`。在范围内选最近的合法步点，覆盖负最小值、小数步距、步距不整除区间、百分比换算与浮点边界；用原生控件实际值验证模型，而不是拿模型测试自己。
3. 单一绑定描述同时驱动“生成写入步骤”和“预测读回”。目前只有部分表共享，算法开关广播、参数与读回仍手写；不再复制第三套语义。
4. 把用户控件事件中的“设参数”与“复位／提示／清历史”等副作用分开。档案 commit 直接应用已经准备好的配置与展示结果，不用反复 dispatch 真实事件来验证或回滚。
5. 提交阶段设统一异常边界。优先采用构造候选状态后切换引用、不可失败的赋值集中提交；无法避免的可失败步骤必须有回滚快照。清空历史、停止采样、重置本轮等不可逆动作放到配置与展示成功之后。
6. 明确失败时不变集合：配置、完整估计器运行态、A/B 克隆与冻结参数、曲线和记录内容、回放游标／积压、校准样本与 pending/window、loop/preset/note、播放态、提示计数。错误结果由返回值表达；正常文件入口允许显示**一次错误反馈**，不应要求连错误反馈也完全不变。

### 永久反例与验收

- 合法配置在“文案构造前、状态写入中、渲染提交中”分别注入一次失败，确认未留下半提交状态。可使用测试适配器／可控写入器，不向生产暴露任意故障开关。
- 当前已勾闭环，目标为 `coordinatedTurn`，另带自定义步距与边界数值；通过真实控件及文件入口验收。
- 快照比较完整内容或可靠的逐元素摘要，不能仅比数组长度、四元数或加权和；加权和会碰撞，`NaN` 经 JSON 还可能变成 `null`。
- 成功导入只复位一次，A/B 关闭及未恢复项说明明确；失败后播放可继续，旧曲线与记录可正常导出。
- 现有坏 `run` 元数据测试保留并改名为“解析提前拒绝”；它不再被当作“渲染异常回滚”的证据。

## 7. SW-05：修复超时后的迟到完成与资源计账

### 现状与反例

**已复现（可控 Promise 与生产调用提取）**：

- 外层 setup 超时后 `dispose()` 返回成功，原始操作却仍未结束；迟到成功且补偿关闭失败时，待清理数已经是 0。
- 旧操作迟到完成后可关闭已经被新会话使用的句柄。
- 通知 start 超时后，迟到 start 可重新启用已废弃订阅；旧 stop 迟到可停掉已提交的新订阅。
- 两次 close 交错完成会产生两次 `onClose(true)`，使总计数隐藏另一条仍存活的会话。

以上仅讨论接口层软件时序，不推断任何外部环境必然出现这些交错。

### 修改位置

[`src/core/transport-session.ts`](../src/core/transport-session.ts) 的 `TransportSession`、`SerialTransportSession`、`NotificationSession`；[`src/main.ts`](../src/main.ts) 的会话装配、`CleanupQueue` 与计数出口。

### 具体方法

1. 分开持有 `rawOperationPromise` 与 `uiResultPromise`：UI 超时可以立刻失败，但不得把外层 race 的结束当成底层动作结束。
2. 用单一状态机表达 `opening/active/disposing/quarantined/released`。原始动作未落定时，不得删除 owner、缓存释放成功或允许同句柄接管。
3. 迟到成功通过原会话所有权进行补偿清理；补偿失败继续保留重试责任。清理结果不确定必须在状态／计数中可见，不能只靠“尽力而为”后静默返回。
4. 每个句柄仅保留一个在途 close。超时后继续观察同一个 Promise，不另发并行 close；关闭成功收敛到幂等的 `opened → closed` 转换，最多记账一次。
5. 通知 start/stop 原始动作保持串行追踪。超时特征先隔离，旧动作真正完成并完成补偿后才允许复用；版本号只能挡回写，不能代替补偿。
6. 页面、重连、切换来源、旧回调早退都用同一释放入口。摘监听与禁止旧数据投递应立即生效，后台清理则保持有界等待、可观测与幂等。

### 永久反例与验收

扩充 [`scripts/lifecycle-contract.test.ts`](../scripts/lifecycle-contract.test.ts)，用 deferred Promise 明确控制每个完成点，不依赖长 sleep：

- setup 超时 → dispose → 原始操作仍挂起 → 尝试复用；新会话不得被允许越过未释放租约。
- 迟到 open/connect 成功，随后 close 拒绝或超时；待清理责任不丢失。
- 旧 close 与新操作交错、旧通知 stop 在新 start 之后完成、旧 start 在 dispose 之后完成。
- 两个独立会话中仅释放一个，总打开计数必须仍为 1；每会话成功关闭回调最多一次。
- 模拟恢复后所有可清理资源收口；永久挂起则保持明确隔离／失败状态，不把计数清零当成功。

浏览器冒烟用本地 API 替身调用生产连接按钮、重选和切源入口，不直接抓旧 session 手工 dispose 来替生产完成清理。

## 8. SW-06：让证据索引与报告相互核验

### 现状与反例

**已复现（内存重放）**：报告正文为失败或旧源码，修改文件哈希后，索引仍可声明当前源码／PASS 并通过检查；报告实际平台与索引平台也未交叉核对。当前源码摘要与现有 dist 哈希并列记录，不能自动证明“该 dist 由该源码构建”。

### 修改位置

[`scripts/evidencecheck.mjs`](../scripts/evidencecheck.mjs)、[`scripts/source-digest.mjs`](../scripts/source-digest.mjs)、[`scripts/soak.mjs`](../scripts/soak.mjs)、[`scripts/ci-run-smoke.mjs`](../scripts/ci-run-smoke.mjs)、[`scripts/visual-evidence.mjs`](../scripts/visual-evidence.mjs)、[`vite.config.ts`](../vite.config.ts)。

### 具体方法

1. 为每种报告定义严格解析器和纯 verdict 函数。索引中的 result、平台、浏览器、源码摘要、产物摘要与起止时间必须取自报告并交叉核对；不能仅验证 sha256。
2. 先检查结构，再访问路径或执行 Git 查询。畸形 entries、重复 id、缺字段、越界路径、未知版本返回明确失败，不让校验器因 TypeError 退出而失去诊断。
3. 构建阶段生成独立 `build-provenance.json`，记录输入摘要、工具／依赖版本、commit、工作树状态及唯一 build id。产物摘要采用统一“相对路径规范化＋文件内容”算法；明确排除自引用的 provenance 输出，避免哈希递归。
4. 页面、Worker 和采集脚本读取同一个 build id。测试开始前核对被服务的构建身份，报告结束时确认源码与产物未变化；发现变化就把整次验收标无效，而非给旧结果贴新摘要。
5. 当前 `sourceDigest` 仅覆盖产品输入，可保留该范围，但另外记录验收脚本／配置摘要和命令行。产品不变、量具改变时不得默默重标旧报告为新判据下通过，应另生成派生复核记录并保留原件。
6. 区分 `latest observation`、`matches current source`、`current deployed build`、`accepted`；最近一次 FAIL 可以是最近观测，但不能被渲染成“当前验收通过”。跨环境唯一性保持 `kind@environment`。
7. 截图报告与长稳／CI 统一 `distHash` 定义。像素证据存在时核图像哈希；不随仓库分发的图像明确标记，并提供可取回的 artifact 地址，禁止只检查 JSON 就声称视觉已验收。

### 永久反例与验收

新增独立证据契约文件（实施时挂入 `contracts`），覆盖：

- manifest PASS／报告 FAIL；正确文件哈希但源码、平台、浏览器或 dist 不一致。
- 修改源码后测试旧 dist；报告采集中途重建 dist；只伪造 metadata、不修改原报告。
- 空 entries、重复 current、断裂 supersedes、缺图像／错误图像哈希。
- 良好报告正常通过，错误报告给出字段路径及原因；默认检查与严格验收模式的证明范围分别写清。

**验收标准**：`evidencecheck --require-source` 只有在“报告正文结论正确、索引一致、构建来源一致、被测服务身份一致”时才能称为当前产物验收证据。

## 9. SW-07：完整跨平台稳定性与 CI 登记

### 现状与反例

**已复现（登记逻辑内存反例）**：普通 `gate` job 成功，或名为稳定性的 job 内部冒烟步骤 skipped，都可能登记成稳定性 PASS；驱动器没有强制五轮完整用例集合，`classifyRun(0, "")` 还能判 pass。warning-only 情况也需统一 summary、退出码与 verdict。

本机五轮报告是已有观测，保留；它不能替代当前提交的另一平台报告。超时字符串只表明未按时就绪，可能来自页面死锁、脚本错误或运行环境，**不能自动当成容量根因**。

### 具体方法

1. 从单一测试清单声明分片及稳定 test id，测试结束写结构化 `completed` 标记和每项状态。验收比较**完整集合**，不能只数 PASS 行或只看退出码。
2. 统一 `runShard`、both 合并、summary 与最终退出码的 verdict 函数：任一断言失败、warning、重启、缺失项、重复项、跳过项或无结束标记都不能是 PASS。
3. `register-ci-run` 默认只接受指定 workflow、稳定性 job 和对应 attempt；核验冒烟 step 实际运行、参数 `runs=5`、两片均完成，以及 artifact 中五轮结果。
4. 登记记录用 workflow/run/job/attempt/environment 标识，避免同 OS＋短 SHA 的多个 job 互相覆盖；`--current=true` 不能绕过来源与内容校验。
5. 将失败先分为断言失败、执行未完成、环境启动失败、根因未知；只有额外的资源／页面就绪／进程状态证据支持时才写“容量”。分类不改变失败结论。
6. 修复共享页面状态污染，给每组测试明确初态和 teardown。等待目标状态而非盲目 sleep；超时有限，超时后保存页面、控制台、时序与任务状态，而不是反复增大 timeout。
7. 本地预检通过后，获授权才把包含改动的提交推到新分支、运行双平台 CI；只新建分支后直接 push **不会上传未提交改动**。

### 执行与验收

```bash
# 本地完整轮；当前命令已存在
node scripts/ci-run-smoke.mjs --shard=both --runs=1

# 跨平台阶段：先获授权，审阅并提交所需文件，确认提交SHA和工作树状态。
# 再通过支持该提交的CI入口运行5轮；不把现有dirty工作树的HEAD当作改动提交。
gh workflow run ci.yml --ref <已推送且包含改动的分支> -f stability_runs=5 -f stability_os=both

# 下列登记命令必须先完成本工单的校验强化，不能仅凭当前脚本返回ok就结案。
node scripts/register-ci-run.mjs --run=<真实运行ID> --job-re="smoke-stability"
```

**结案条件**：同一明确提交在 Ubuntu 与 Windows 各完成五轮、每轮 app/devices 的完整清单、零失败／warning／重启／跳过；报告、CI SHA、构建 provenance 与索引一致。任意一项缺失时保持开放，不提升评分代替证据。

## 10. SW-08：长稳既抗 GC 相位噪声，也能抓住末段增长

### 现状与反例

**已复现**：warm-up 为 15 MB，随后 95 个样本为 15 MB，最后 5 个为 55 MB，增长限制 24 MB。当前返回水位增长 0、端点增长 40、峰值增长 40、全程趋势约 11.29，仍 PASS。

这说明判据存在盲区，**不等于现有真实报告已经发生泄漏**。

### 具体方法

1. 保留水位、峰值与全程趋势，并持续输出原始样本和端点差，避免把 GC 锯齿相位直接判成泄漏。
2. 新增末段检测：最后若干样本持续显著高于前段的稳健基线时，进入追加观察，而不是因为尾窗还含一个旧低点就 PASS。
3. 采用最近短窗分位数／中位数、持续超阈值样本数与局部趋势组合；参数在测试前固定并文档化。样本不够或无法观察到回落时写“证据不足／继续观察”，不默认通过。
4. 正常教学功能仍连续运行；若引入停止负载后的回落观察，必须标成独立尾随阶段，不能代替原本要求的连续 600 秒负载。
5. 检查墙钟覆盖、采样最大空洞、时钟推进、容器上限与批次／事件完整性。浏览器上下文丢失使该次运行无效，保留失败报告，不续跑拼接成连续成功。

### 永久反例与验收

扩充 [`scripts/soak-contract.test.mjs`](../scripts/soak-contract.test.mjs)：

- 稳定 GC 锯齿不同首尾相位均不误报。
- 平台阶跃、最后 3／5／10 个高点、平滑爬升、短峰后回落、末点恰逢 GC、采样缺失／时长不足。
- 末段持续 +40 MB 不能直接 PASS；追加观测后仍高则失败，回落正常才按预设规则判定。
- 同一份原始样本重放结论一致，旧结果与新判据复算分开保存。

## 11. SW-09：实质性能优化与预算口径

### 正确口径

当前全部 JS gzip 约 265 KiB，名义上限 300 KiB，90% 规则下**有效门槛为 270 KiB，距离失败约 5 KiB**。主包 gzip 名义 120 KiB 的有效门槛是 108 KiB。不要把名义“12%余量”写成已减少了传输量。

“vendor 固定，所以应用代码减 30% 也达不到旧预算 10% 余量”的推导不成立：按近似数值，`131 + 134 × 0.7 = 224.8 KiB < 272 × 0.9 = 244.8 KiB`。这不保证该优化容易实现，但不能称为数学上不可能。

### 具体方法

1. [`scripts/distbudget.mjs`](../scripts/distbudget.mjs) 同时输出原始字节、gzip 字节、名义上限、有效失败线、剩余字节、相对冻结基线增量；去掉“抬上限即可”的默认修复提示。
2. 将预算判定抽成纯函数。在 [`scripts/budget-contract.test.mjs`](../scripts/budget-contract.test.mjs) 测真实数值边界：270 KiB 恰通过、增加 1 byte 失败、265 KiB 剩 5 KiB，而非只匹配源码字符串。
3. 用 sourcemap 定量归因：vendor、主页面、数值内核、Worker、文档演示、引导等分别列 raw/gzip。先定位实际重复，再做最小实验；单次材质替换未变小不等于所有方案都无效。
4. 研究主线程与 Worker 的共享模块产物、可裁剪导入及不必要的字符串／诊断代码；保留 Worker 降级与核心教学功能。仅把代码搬入 lazy chunk 不算总量减少。
5. 页面性能单独测：首次可交互时间、真实墙钟帧率、长任务、输入延迟、批量取消延迟、内存峰值。不能把经 50 ms 夹紧的仿真 dt 算出的 fps 当作真实性能指标。
6. 每次优化提交 before/after 同环境对照；传输量下降却导致首帧或交互变差时需说明取舍，不以单个数字判优。

### 结案标准

短期先报告真实余量并保持所有现行有效门槛不回退；减重阶段以原聚合预算的 10% 余量目标（约 244.8 KiB）作可验证目标。若实测权衡后需另定标准，必须获得明确决策并保留旧目标、实际差值及用户收益，不能靠改名义上限自动给性能满分。

## 12. SW-10：主线程批量降级的协作取消

### 现状与反例

**已复现**：主线程降级仅在种子间 `setTimeout`，单种子内部同步执行。测试中一个默认 30 秒实验约 548 ms 后才返回，提前排队的取消定时器直到返回后才执行。毫秒值随机器变化，事件循环被同步占用这一事实不变。

2. 设有界计算片预算，并通过 macrotask 让出执行权，给点击、绘制和计时器机会；不要用只让出 microtask 的循环假装可交互。
3. 每次 await、进度回调和结果提交都检查 generation。取消后不加入部分种子的完成统计，不覆盖新任务结果，也不留下旧看门狗。
4. Worker 与主线程路径使用同一结果聚合与任务状态机，界面明确显示当前执行路径。

### 永久反例与验收

- 保留已有同步／异步同 seed 结果深等价测试；增加降级路径实际调用异步 runner 的契约。
- 禁用 Worker，在**首个种子尚未完成时**通过真实 GUI 取消；不只在种子间触发，也不用页面内同步派发事件绕过排队。
- 项目支持的参考环境中，先以取消后下一计算片即停止、交互响应 p95 ≤200 ms 作为验收目标；记录环境与原始时序，达不到先优化片预算而非提高阈值。
- 覆盖快速启动→取消→再启动、错误降级、页面关闭、进度晚到；只统计完整种子，旧 generation 不回写。

- 软件重评分建立在修复后证据上，不预先承诺 95 分或 100 分，也不因工单全部勾选而自动满分。

## 15. 分阶段交付与执行清单

### 阶段 A：正确性与异常安全

先做 SW-01、SW-02、SW-04；并行准备 SW-03、SW-05 的故障注入与异步时序反例。所有失败应先在旧实现复现，再修最小生产路径。UI、数值算法、导入与回放不做无关重写。

**交付**：可复验的错误输入、修复 diff、定向测试、完整 check；用户数据和既有归档格式的兼容说明。

### 阶段 B：可信验收与交互性能

SW-06 → SW-07 的报告链路先修，再完成 SW-08、SW-10；把“报告自己写 PASS”升级为可重放的 verdict。先跑短轮检查量具，确认无恒真断言再投入长稳。

**交付**：报告契约、故意不完整／错配报告必失败的测试、取消时序、环境可复现的 CI 配置。远端执行单独授权。

### 阶段 C：性能、可访问性与收敛

SW-09、SW-11、SW-12；每个优化保留 before/after，最后一次性完成同构建证据采集，不在长测试进行中继续改产品输入。

**交付**：有效预算余量、页面性能对照、视觉与读屏矩阵、同构建稳定性／长稳报告、文档与索引。

### 代码修改后的统一门禁

严格顺序保留项目约定；以下为**未来执行流程**，本次文档整理不重跑长测试：

```bash
npx tsc --noEmit
npm run check
npm run build
npm run budget
npx tsx scripts/doccheck.ts --recompute
```

浏览器单轮使用当前构建，预览统一 4173 端口；源码或入口 HTML 改变后必须重建并强刷。二选一，避免重复起两个同端口服务：

```bash
# 方式一：驱动器负责启动和停止预览；先确认4173未被别的服务占用
node scripts/ci-run-smoke.mjs --shard=both --runs=1 --out=.audit-current/software-plan-smoke

# 方式二：终端A启动预览，终端B跑完整套件
npm run preview -- --port 4173 --strictPort --host 127.0.0.1
npm run smoke
```

全部实现收敛后，先跑稳定性，结束并确认驱动器已关闭预览；再启动同一份 dist 的预览，**顺序**运行两份长稳与视觉，避免资源竞争污染结论：

```bash
node scripts/ci-run-smoke.mjs --shard=both --runs=5 --out=.audit-current/software-plan-stability

# 另一个终端启动同一份dist的预览；下列命令沿用同一构建，不在中间再build
npm run preview -- --port 4173 --strictPort --host 127.0.0.1
node scripts/soak.mjs --batch=true --seconds=600 --output=docs/generated/soak-batch-600-<build-id>.json
node scripts/soak.mjs --reconnect=true --seconds=600 --output=docs/generated/soak-reconnect-600-<build-id>.json
npm run evidence:visual -- --out=screenshots/visual-<build-id> --report=docs/generated/visual-<build-id>.json
node scripts/evidencecheck.mjs --require-source
```

将 `<build-id>` 替换为实际值；创建新报告，不覆盖旧失败记录。当前命令存在不等于已经具备本方案要求的加强判据，SW-06～SW-08 完成后才用于最终结案。
