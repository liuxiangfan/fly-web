- 上一轮重新运行了类型检查、`npm run check`、独立临时目录构建、现存产物预算、文档全量复算与严格证据检查，结果通过。
- 现有 Windows 摘要记录五轮、每轮96项通过；两份600秒报告有3/3批次和66/66恢复记录。它们是有价值的观测，仍需补齐报告正文、构建来源与验收脚本身份交叉验证。
- 现有UI/runner/Worker/回放对拍覆盖默认组合、长间隔背压和部分异常输入；不能据此扩称全部校准、前端滤波与非零粗对准组合已验收。
- 档案预检能提前拒绝多种不可表达配置；但“提前拒绝不改状态”不等于“提交中任何异常都完整回滚”。
- 已有截图、布局与可访问性检查保留；DPR2配半尺寸CSS视口不能替代纯文字放大200%，ARIA存在也不能替代真实读屏验证。
- 全部JS gzip约265 KiB。名义上限300 KiB配90%规则，实际门槛270 KiB，剩余约5 KiB；名义12%不能直接视为产品性能改善。

详细历史数据保留在 [验证证据记录](VERIFICATION-EVIDENCE.md)。其中早期宽泛结论需结合本页及实施方案的边界阅读，不能仅凭旧PASS判断新工单已完成。

## 5. 何时重新评分

完成相应工单后再评对应维度，不预先承诺分数增长。重评分至少要求：

1. 已复现的时间、遥测、档案与异步反例修复，并成为永久测试。
2. 完整门禁在修复后的构建上通过；现有通过项不被删减或弱化。
3. 报告与索引交叉一致，源码、产物、量具版本及实际执行范围可追溯。
4. 跨平台稳定性确认五轮完整清单；超时原因未查明时保留不确定性。
5. 长稳同时通过GC抗噪和末段增长检查；视觉、键盘、文字放大与读屏分别有证据。
6. 实质性能改善有同环境前后数据；文档明确有效门槛、实际剩余字节与取舍。
