## 6. TQ-01：固定练习配置彻底隔离现场

### 6.1 确认事实

位置：`src/ui/learning-panel.ts:113–179`、`:225–237`、`:1121–1129`。

当前流程是：

```text
读取当前现场配置
→ 深拷贝
→ 覆盖本题 patch 中出现的字段
→ 运行
```

未出现在 patch 中的字段继续来自现场。UI 却说明“不读取现场滑块”。

### 6.2 独立生产探针结果

| 活动 | 现场扰动 | 基线结果 | 扰动后结果 |
|---|---|---:|---:|
| `drift-linear-10s` | `imu.gyroWalkDps: 0→0.5` | pure.max 19.830005933450877° | 9.308185766714939° |
| `sensor-delay-omega-tau` | `imu.sensorBandwidthHz: 0→5` | pure.max 6.015469218379962° | 13.287946927164569° |

两题题面与预测区间未改变，结果却落到区间外。不是 runner 错误，而是固定题目继承了题面以外的合法扰动。

其他复核探针发现：偏航题继承较小 Kp、Ki=0、大零偏时，标准正确集合可被判错；Ki 题继承 `steadyFromSec=30`，超过其 20 秒证据窗口，导致证据不可用。

### 6.3 实现方法

1. 固定题目从 `defaultExperimentConfig()` 或专用教学基线构造，不从 `deps.currentConfig()` 构造。
2. 显式定义固定种子，或定义明确的变式种子策略；普通“重试同一题”沿用相同条件。
3. 固定全部 IMU 参数；不只固定题面提到的两三个字段。
4. 清空校准对象并关闭其应用，除非该题明确研究校准；校准模型与应用状态必须成对定义。
5. 固定解算频率、粗对准、初态、稳态窗口、算法参数与磁观测状态。
6. 对题目 patch 重新走生产 schema 校验和规范化，非法题目定义明确失败。
7. 真正的“在当前配置下探索”可以保留，但与固定练习分开标识，不使用固定题目的答案区间判分。
8. UI 的固定条件摘要从最终执行配置生成或核对，避免说明与配置独立漂移。

### 6.4 永久测试

- [ ] 使用两个数值差异很大的合法现场，构造同一固定题目的配置，得到相同规范形与摘要。
- [ ] 扰动种子、随机游走、量程、刻度、失准、带宽、延迟差、采样率、校准及其应用标志，固定题目不受影响。

## 7. TQ-02：偏航题证明实际倾角修正

### 7.1 确认事实

位置：`src/ui/learning-activity-data.ts:82–104`。

当前证据设置纯偏航 30° 初始误差，没有注入倾角误差，却将 `tiltRmse≤5°` 用于判断“加计可以修正倾角偏差”。

独立反例将 Kp=Ki=0、关闭启动放大和粗对准，并归零噪声及扰动：

```text
tiltRmse ≈ 3.95e-14°
yawRmse = 30°
包含“倾角可以被修正”的标准集合仍得到 passed=true
```

低误差不等于有纠错发生。算法从头到尾不修正，也能满足该判据。

### 7.2 实现方法

建立两个明确的证据组，不让一条纯偏航轨迹证明全部命题：

- **倾角组**：注入非零倾角初始误差；固定有效加计、非零观测修正增益；比较开始／结束误差，或加计修正开／关两侧。
- **偏航组**：注入纯偏航初始误差，关闭磁修正；使用明确条件验证重力不能消除绕重力轴的偏差。

禁止仅用全程 tilt RMSE 低于阈值表达“纠错成功”。至少应有：

1. 实际存在初始倾角误差；
2. 观测修正实际启用／应用；
3. 与无修正负对照相比有可验证的误差下降。

可以用已有 runner 的初态、最终四元数或详细序列实现，不必新造算法。

### 7.3 永久测试

- [ ] 有明确非零初始倾角误差，修正组收敛，无修正组保留偏差。
- [ ] Kp=Ki=0 的反例不能通过“发生倾角纠错”的证据判断。
- [ ] 纯偏航组关闭磁修正后保留偏航偏差。
- [ ] 正确／错误选项由各自证据支持；固定几何事实明确标为理论说明，不包装成实测结果。
- [ ] 不用自动粗对准的重置代替算法观测修正却不告知用户。

## 8. TQ-03：Ki 题限定条件与结论

### 8.1 确认事实

位置：`src/ui/learning-activity-data.ts:114–169`。

当前 A/B 只要求 `B.steadyRmse < A.steadyRmse`，但题目选项包含长期趋零和可能振荡等更强结论，且仍可继承磁修正关闭状态。

独立反例，关闭所有磁修正后：

| 侧 | 稳态 RMSE | 偏航 RMSE |
|---|---:|---:|
| A：Ki=0 | 12.352423660963849° | 8.728706816206161° |
| B：Ki=0.05 | 12.290856019421346° | 8.750083876109306° |

总误差微小下降仍得到 passed=true，偏航并未被消除。

### 8.2 实现方法

1. 与 TQ-01 共用固定教学基线；明确磁修正是否开启及其可信条件。
2. 题目默认只验证当前窗口可支持的命题，例如“20 秒窗口内加入积分项降低稳态误差”。

## 10. TQ-05：统一历史帧、Inspector 与游标所有权

### 10.1 确认事实

- `src/ui/telemetry-diagnostics.ts:271–272` 保存帧时可附加 ESKF 快照。
- 同文件 `:194–197` 的 Inspector 仍读取 `latestEskf ?? deps.getKalmanSnapshot()` 和 `deps.getTime()`。
- 同文件 `:158–172` 的观测面板仍读取当前估计器及当前真值。
- `src/main.ts:3225–3245` 的鼠标／键盘直接修改游标；`mouseleave` 清游标，不通知回看控制器。

因此目前是“历史模型与回看文字 + 实时诊断信息”，不是各面板同帧的完整复盘。仅保存快照字段不足以关闭这项需求。

### 10.2 实现方法

1. 由回看控制器提供当前选中帧的只读查询或选择通知；用同一来源驱动所有应联动的展示。
2. 回看有效时，Inspector 读取该帧 `eskf` 和该帧 `t`。
3. 该帧无快照时显示“此历史帧未记录内部量”，不回退实时或相邻帧。
4. 实时 Inspector 也需要将快照与其实际采集时刻绑定；低解算频率时不以世界最新时间冒充快照时刻。
5. 回看激活时，观测状态／误差面板若仍实时显示，必须明显标“实时”；更优方案是切换为该历史帧，保持一致。
6. 定义游标模式：`live / hover / history-locked`，锁定回看不能被鼠标离开曲线静默清除。
7. 事件、键盘、曲线拖动选择历史时刻，应通过统一选择出口；超容差只显示曲线值，不假造姿态快照。
8. 返回实时时统一清理覆盖与历史锁定，并显示最新生产状态。
9. 同 runId 切换算法时保留帧自身算法 ID；不能把当前选择的算法名称贴到旧帧。

### 10.3 永久测试

- [ ] 构造两个 t 不同、K/dx/P 等内部量明显不同的真实采集帧；切帧后 Inspector 的时间和内容同步改变。
- [ ] 历史帧没有 ESKF 快照而实时有快照时，Inspector 明确缺失，不展示实时快照。
- [ ] 回看中鼠标进入／离开曲线，历史锁定不被无意清空。
- [ ] 从曲线、键盘和事件选择同一时刻，回看帧、三图、模型和内部状态一致。
- [ ] 重置、换源、停止采集后没有旧 runId／旧快照泄漏。

## 13. TQ-08：证据索引与历史像素声明收敛

### 13.1 发现

- 旧 CI 和线上部署条目仍有 `current:true`，其源码不属于本次教学构建。
- `SOURCE_BOUND` 的硬绑定集合不覆盖 GitHub Actions／postdeploy 类型。
- 历史像素覆盖例外限定为 `current=false + localOnly=true + pixelsOverwritten=true`，没有自动验证覆盖来源与前后关系。
- 当前视觉条目存在“报告 PNG 不随仓库分发”与索引 `localOnly:false` 的声明差异。

当前本机六条报告和像素确实匹配；不能因这些声明问题否认实际通过。但也不能将所有 current 都视为新版本验收。

### 13.2 修复方法

1. 分清本机当前验收、当前线上部署和历史 CI，不用一个含糊 current 对外声称全新版本就绪。
2. 历史记录不删除，按种类／环境标注 accepted source 和 applicable source。
3. 当前没有新 CI 时明确显示“当前源码 CI 未执行”，不借旧 run 补齐。
4. 今后截图按 sourceDigest／buildId／采集 ID 存入新目录，避免相同 HEAD 的 dirty 构建覆盖旧图。
5. 对已经丢失的历史像素写“报告保留、像素不可复核”，不能恢复成通过声明。
6. 如保留覆盖例外，记录覆盖者、原路径、旧／新报告和采集时间，并验证关联；例外不得影响当前像素严格校验。
7. `localOnly` 对报告与截图集合的含义写清；需要区分时使用分别的字段，不让校验依赖误读。
8. 对默认校验／严格校验各自证明范围添加反例。

任何远端 CI 拉取、推送或发布操作仍需授权；本项可先在本地修正标签与判定。

## 14. TQ-09：体积与演进余量

### 14.1 实测事实

独立教学／诊断 chunk 的余量不能抵消聚合总闸。名义上限下有 10% 余量，不表示距有效失败线还有 10%。

### 14.2 优化顺序

1. 先估算 TQ-01～06 正确性修复的实际增量，再选小规模实现。
2. 消除重复格式化、单位／标签／文案和重复配置处理；不删除状态解释或反例。
3. 按实际 chunk 图决定共享与分组；lazy 只改善首屏，仍计入总 JS。
4. 文本数据按需加载时继续计入总产物及离线缓存，不能藏预算。
5. 保存修复前后 raw/gzip、首屏、解析／输入延迟与内存数据。
6. 如仍超线，报告缺口、归因和候选取舍，等待用户决定是否调整预算；既有 P2 不构成无限次抬线授权。
