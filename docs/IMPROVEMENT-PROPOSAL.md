## 0. 结论摘要

项目在「教学装置」这个定位上已经相当完整：五算法同屏、误差链可调、三视图、
95 项静态自检 + 43 项浏览器冒烟、应用内 19 章数学文档与 13 步引导课程。继续做加法的边际收益，主要不在「再加一个算法」，
而在**补齐三条叙事链**和**把已有数字变成可交互的因果**：

1. **机械现象 → 算法后果的桥**：万向节锁现在只在环架视图里演（机械视角），
   主视图的算法对比里**从来没有出现过锁**——`pitch` 剧本最大 ±45°，`violent` 最大 ±60°。
   本文实测出这条桥的量化证据（见 §2.1）：**俯仰恰 90° 时互补滤波姿态崩坏 135°，
   而 Mahony/Madgwick 纹丝不动（0.03°）**。这是全项目最有价值的一处缺口。
2. **简化处 → 标准做法的桥**：Madgwick/Mahony 的 MARG 目前是「磁只约束偏航」的简化版，
   文档也如实标注了，但**从未展示标准做法**（构造 `b=[0,bx,0,bz]` 做磁倾角补偿的完整磁场向量版）。
   补一个可选模式 + 对照章，就把「为什么工程实现要这么绕」讲透了。
3. **不确定度 → 增益的桥**：卡尔曼章节有三层直觉的文字，但**没有任何可视化的协方差**。
   业界最好的卡尔曼讲解（bzarg「How a Kalman filter works, in pictures」）靠的就是误差椭圆/高斯叠加。

另有三类工程性改进：文档全文搜索（文档已占 index.html 的 85%）、门控的滞回恢复、
以及构建产物里 1.14 MB 从未被引用过的 KaTeX 字体。

## 1. 实测证据（本文档独有，非推测）

### 1.1 互补滤波在万向节锁处的崩坏（探针脚本已删除，数据保留）

方法：真值姿态 = `qFromEuler(roll, pitch, 0)`，固定 pitch、让 roll 从 0 扫到 90° 共 6 s；
机体角速度用解析式 `ω_body=[φ̇,0,0]`（ZYX 内旋、θ 恒定）；所有估计器从真值起点 `reset(q0)` 出发
（否则测到的是初始偏差暂态）；采样 500 Hz。比较最大姿态误差（`qAngleBetween`，度）。

**理想传感器（无噪声、无零偏）：**

| 俯仰角 | 互补滤波 | Mahony | Madgwick |
|---|---|---|---|
| 85° | 0.030° | 0.030° | 0.099° |
| 89.9° | 0.030° | 0.030° | 0.030° |
| **90.0°** | **134.960°** | 0.030° | 0.030° |
| 90.1° | 0.030° | 0.030° | 0.030° |

**真实器件级噪声（陀螺 0.2 °/s、加计 0.2 m/s²、零偏 1 °/s）：**

| 俯仰角 | 互补滤波 | Mahony | Madgwick |
|---|---|---|---|
| 85° | 5.03° | 4.60° | 4.57° |
| 87° | 9.24° | 4.60° | 4.56° |
| 88° | 16.47° | 4.59° | 4.56° |
| 89° | 23.19° | 4.59° | 4.55° |
| 89.5° | 29.51° | 4.59° | 4.54° |
| **90.0°** | **68.07°** | 4.58° | 4.54° |
| 91° | 16.40° | 4.57° | 4.53° |
| 95° | 5.66° | 4.53° | 4.47° |

**读法**：无噪声时是**测度零的奇点**——89.9° 与 90.1° 都完好，只有恰 90.0° 炸掉；
但只要有一点噪声，误差就随接近 90° **单调放大**（互补 85°→5°，89°→23°，90°→68°），
而四元数空间的 Mahony/Madgwick 全程平在 4.5°（那 4.5° 是 1 °/s 零偏带来的偏航漂移，与俯仰无关）。

**根因**（`src/estimators/index.ts`）：互补滤波工作在欧拉角空间——
`yaw` 取 `qToEuler(qGyro).yaw`，再用 `qFromEuler(rollAcc, pitchAcc, yaw)` 重建姿态。
pitch → ±90° 时 roll/yaw 在欧拉参数化下不可分辨，重建出的姿态就是错的。
四元数空间的 Mahony（`e = a × ĝ`）与 Madgwick（梯度下降）没有这个参数化奇点。

**教学价值**：这条正是「为什么姿态解算用四元数而不是欧拉角」的**当场可复现证据**，
而且它与「万向节锁」视图讲的是同一件事的机械面——两个视图之间目前缺的就是这条连线。
现有实现只需加一个剧本，不需要改动任何算法。

### 1.2 构建产物中的死字体

- `dist/` 总计 2.6 MB，其中 **1.17 MB（45%）是 KaTeX 字体**：20 个 ttf（540 KB）+ 20 个 woff（336 KB）+ 19 个 woff2（292 KB）
- 来源：`src/main.ts:2` `import "katex/dist/katex.min.css"`
- 而 `src/style.css:1537` 只用了 `font-family: "KaTeX_Main"` 一个族
- 影响评估（如实说明）：浏览器按 `unicode-range` 只下载用到的字面，**运行时流量影响很小**；
  但产物里 44% 是永不引用的文件，对自托管镜像、缓存清单、构建审查都是噪音。
  woff/ttf 两套在 2026 年已无必要（woff2 全支持）。
- 修法：改为手写 3–4 个 `@font-face`（KaTeX_Main-Regular/Italic/Bold，仅 woff2），
  与项目自托管 Fira 字体（`src/fonts.css`）的做法完全一致。

## 2. 建议清单（按主题，含优先级）

### P1 · 教学价值最高

#### 2.1 把万向节锁接进算法对比：新剧本 + 新章「同一个 90°，两种视角」

- **做什么**：`core/scenarios.ts` 加两个剧本——`pitchSweep90`（俯仰 0→180° 慢扫，穿越 ±90°）
  与 `pitchHold90`（俯仰停在 90°，横滚来回摆）；主视图误差曲线上就会出现
  「互补滤波在穿越点尖峰、四元数算法平坦」的图像。
  文档加一章，左侧摆环架视图截图（轴重合变红），右侧摆主视图曲线截图（互补尖峰）。
- **为什么**：这是本装置两个视图之间唯一缺失的连接，也是「四元数 vs 欧拉角」最硬的论据。
  实测数字（§1.1）直接可用作章节里的读数。
- **成本**：剧本 ~20 行 + 一章文档 + 一条 selftest 断言（互补在 90° 误差 > 30°、Mahony < 1°）。
- **注意**：剧本停在 90° 会让互补滤波的误差曲线长期悬在高位——这**正是要展示的**，
  但要在文案里说清「这不是 bug，是参数化奇点」，否则会被当成缺陷报告。
  建议同时提供「90.000°」与「89.5°」两个预设，让读者自己看到奇点 vs 病态的区别。

#### 2.2 文档全文搜索（Ctrl/⌘+K）

- **做什么**：构建期把 7 个 `.doc-page` 抽成倒排索引（章节 id + 标题 + 正文纯文本），
  文档层加搜索框，结果项 = 「章标题 + 命中片段」，回车跳转（复用现成的 `showDocPage` + `jumpToHash`）。
- **为什么**：230 KB / 21 章 / 3 模块，无检索手段；读者知道「有个门控的东西」却找不到。
  这是纯增量、不改任何现有结构的最大可用性改善。
- **成本**：一个 `scripts/buildSearchIndex.ts`（parse5 已在 devDependencies 里）+ 一个搜索 UI 块。
  现有 `htmlcheck` 的 parse5 用法可直接复用。

#### 2.3 完整 MARG（磁倾角补偿）作为可选模式 + 对照章

- **做什么**：Mahony/Madgwick 增加一个 `magMode: "yaw-only" | "full"`。
  `full` 走文献标准构造：`h = q ⊗ m ⊗ q*` → `b = [0, √(hx²+hy²), 0, hz]`，
  目标函数里重力项与磁场项**并列**（Madgwick 2011 原式），而非只取 z 分量。
  文档加对照节：简化版（本项目现状）vs 标准版，各自在「机体倾斜 + 硬铁」下的行为差异。
- **为什么**：这是目前实现与文献**唯一实质性的偏离**，文档如实标注了（index.html:1804、
  f-madg 页「本装置用独立偏航方向分量简化」），但从未展示标准做法是什么样。
  补上之后，「磁力计为什么能同时校正倾角」这个问题才有答案。
- **出处**：[ahrs 库 Madgwick 文档](https://ahrs.readthedocs.io/en/latest/filters/madgwick.html)
  （给出 `b=[0,b_x,0,b_z]`、`b_t=[0,√(hx²+hy²),0,hz]`、`β=√(3/4)·ζ̄` 与完整 `f_b/J_b`）；
  原始报告 Madgwick 2011 internal report。

#### 2.4 卡尔曼不确定度可视化 + 一维卡尔曼 playground

- **做什么**：
  1. 玻璃盒面板新增「协方差」块：从 `KalmanEstimator` 暴露 3×3 姿态块 `P[0..2][0..2]`，
     在 3D 视图画**误差椭球**（预测 → 更新两次收缩，用两个颜色/透明度区分），
     或在小 inset 里画 2D 误差椭圆 + 增益 K 的数值。
  2. 文档卡尔曼页加第 5 个 Canvas 演示：一维「两台秤」交互——两个滑块调先验方差 σ₁² 与观测方差 σ₂²，
     实时画出两条高斯曲线、乘积后的后验、以及 K = σ₁²/(σ₁²+σ₂²)。就是现有三层直觉里
     「两台秤的最优加权」那句话的动态版。
- **为什么**：文档已有「协方差椭圆」的**文字**直觉，却没有任何可视化；
  而业界公认最好的卡尔曼讲解（bzarg 图文、
  [How a Kalman filter works, in pictures](https://www.bzarg.com/p/how-a-kalman-filter-works-in-pictures/)）
  正是靠高斯斑块叠加 + 协方差椭圆讲通的。本装置有 `getCovariance()` 快照接口，接可视化成本低。
- **成本**：中等。椭球可用 `THREE.Mesh` + 缩放矩阵；一维演示是一个新 Canvas（与现有 4 个同构）。

#### 2.5 互补滤波的频域视图（伯德图 / 交叉频率）

- **做什么**：文档 filters 页加一个 Canvas 演示：横轴频率对数轴，画陀螺通道的高通
  与加计通道的低通，两条曲线交点即交叉频率；滑块调 α（或 Mahony 的 Kp），交点实时移动。
  面板标注「Kp = 1.0 ⟺ 截止 ≈ 1 rad/s（时间常数 ≈ 1 s）；振动频率 31 Hz 落在哪一侧」。
- **为什么**：文档已经用频域解释了互补滤波（fd-comp-3「为什么叫互补——频域视角」），
  但停留在公式。把 α / Kp 与**截止频率的物理量纲**连起来，学生才能按传感器噪声和
  桨叶通过频率去设参数，而不是「调大一点看起来好了」。
- **出处**：Kp 作为环路带宽的解释可从 [ahrs Mahony 文档](https://ahrs.readthedocs.io/en/latest/filters/mahony.html)的
  ECF 方程线性化得到；该文档给出 `k_P=1.0, k_I=0.3` 默认值但未展开带宽映射（本建议属于推导补充）。

### P2 · 工程性与鲁棒性

#### 2.6 观测门控：阈值可调 + 滞回恢复

- **现状**：`ACCEL_GATE_DEG = 20`、幅度 35% 是**硬编码常量**，UI 只有一个总开关；
  拒收是逐帧无记忆的（`accelGateActive()`）。
- **建议**：
  1. 把两个阈值做成滑块 → 用户能当场看到「阈值太松 → 污染穿过；太紧 → 正常机动被误拒」的 U 形权衡；
  2. 加**滞回/恢复窗**：工业库 Fusion 的做法是「连续 5 s 内 90% 的样本都被拒 → 判定为需要重新收敛 →
     临时放宽门控把估计拉回」，避免在阈值边界反复横跳。本装置现在是纯硬门限。
- **为什么**：项目自己的文档（f-compare）已经写明 Fusion 是「10° 方向拒绝 + 5 秒恢复窗」，
  但**代码里没有恢复窗**——文档与实现的这处不一致值得补齐，且它本身就是很好的教学点
  （「为什么要滞回」= 控制里的抖振问题）。
- **成本**：小。`Estimator` 加一个拒绝历史环形缓冲即可；自检可以 A/B 出「有/无滞回的抖动次数」。

#### 2.7 传感器物理效应补全（四个滑块）

按「用户能立刻看出因果」排序：

| 新滑块/开关 | 现象 | 为什么值得做 |
|---|---|---|
| **陀螺仪量程饱和**（±250/500/2000 °/s 档位） | 剧烈机动时读数被截断 → 积分姿态大幅跑偏 | `violent` 剧本现在不截断，与真实器件不符；这是「飞控为什么怕翻滚」的直接原因。**业界处理**：检测饱和 → 抬高陀螺噪声 R / 靠向量修正拉回 |
| **传感器延迟**（0–20 ms） | 加计/磁观测滞后 → 修正相位落后 → Mahony 增益一大就振 | 仿真现在假设零延迟同步采样；真实 MEMS 有传输+滤波群延迟。用它可以把「Kp 加到某个值开始振荡」解释成相位裕度问题 |
| **解算频率**（50/100/200/500 Hz） | 低采样率下指数积分与一阶积分的差别、以及高动态下的跟踪损失 | 项目**已经**用了精确指数积分（相对多数玩具实现的优势），但没有可见的对照系——把它做成可调，才有说服力 |
| **陀螺刻度因子 + 安装失准**（0.1–2%） | 速率相关的姿态误差，**6 维 ESKF 不可观、无法被零偏估计吸收** | 这是加计已有交叉轴、陀螺侧缺失的对称项；也是「为什么零偏估计救不了刻度误差」的好教材 |

- **出处**：陀螺刻度/非正交模型 `ω_m = (I+S+N)·ω_true + b_g` 与标定方法见
  [arXiv:1707.07082](https://arxiv.org/abs/1707.07082)（磁力计辅助的陀螺标定）、
  [arXiv:2103.11096](https://arxiv.org/abs/2103.11096)；
  加计六面标定的完整最小二乘（解 offset + 3×3 刻度/交叉轴）见
  [ADI AN-1057](https://www.analog.com/media/en/technical-documentation/application-notes/AN-1057.pdf)
  （并给出「50 mg 零偏 → 2.9° 倾角误差」这类可引用的量级）；
  MathWorks `gyroparams` 把 ConstantBias / BiasInstability / RandomWalk / ScaleFactor / Misalignment /
  TemperatureBias 全部参数化，可作为滑块命名与分组的参照。

#### 2.8 数据导入与离线回放

- **现状**：只有导出（CSV）。无法把一份真实录制的 IMU 数据（或别人的数据集）喂回来做离线对比。
- **建议**：加一个「导入」入口，接受两种格式：① 本装置导出的 CSV（含参数头）；
  ② 通用六列文本（`t, gx, gy, gz, ax, ay, az[, mx, my, mz]`，单位可下拉选 °/s 或 rad/s）。
  导入后停用仿真，用与真实串口**同一套**帧队列/时钟路径回放，五种算法照常跑、曲线照常出。
- **为什么**：① 教学上「拿你自己的飞行日志回来复盘」比任何合成数据都有说服力；
  ② 让真实串口模式的那套 `serialState.queue` + `state.simTime` 架构再复用一个消费方，
  验证它确实与数据来源解耦；③ 顺带解决「用户没有硬件也想看真实噪声形态」的问题。
- **注意**：与 2.7 的「采样率可调」共用同一处时钟逻辑，建议一起设计。

#### 2.9 CSV 导出补四元数列

- **现状**：`exportCsv()` 只导出欧拉角，回调里也注释了「参数头部」。想做四元数分析（例如复现双重覆盖、
  检查符号连续性）必须自己从欧拉角反算。
- **建议**：表头补 `q{w,x,y,z}_<est>` 共 5 算法 × 4 列（或提供「导出内容」复选：角度 / 四元数 / 原始 IMU）。
- **为什么**：成本几乎为零（`est.q` 就在手边），但对做作业/写报告的人直接可用。

#### 2.10 CI 补浏览器冒烟 + 构建预算

- **现状**：CI 只有 `tsc → check → build`。`npm run smoke`（真浏览器端到端，含假 Web Serial 端口）
  **不在 CI 里**——意味着部署流水线不会拦住渲染层的回归。
- **建议**：CI 加一步 `npm run build && npm run preview &` + `npm run smoke`
  （Ubuntu runner 需装 Chrome：`browser-actions/setup-chrome` 或 `apt-get install chromium`，
  并让 `scripts/browser-smoke.mjs` 支持 `CHROME_PATH` 环境变量覆盖——它现在「自动找本机 Edge/Chrome」）。
  同时加一个产物预算断言（例如 `dist/assets/*.js` 总量与字体文件数上限），防止 §1.2 那类膨胀回归。

#### 2.11 色盲友好配色

- **现状**：`纯积分 #f85149`（红）与 `Madgwick #7ee787`（绿）是经典的红色盲混淆对；
  `互补 #ffa657`（橙）在红绿色盲下也偏红。曲线有 6 至 12 条同时在场，只靠颜色区分是有风险的。
- **建议**：加一个「高对比配色」开关（`body[data-palette=cb]`），换成
  蓝/橙/紫/黄/青/白（色相分离度 ≥ 60°），并保持**线型**区分（已有 B 组虚线，可给其它系列也加
  点划/双线变体）。配色应继续写在 JS 里与 CSS 令牌区分（沿用现有约定）。
- **为什么**：项目已经为可访问性做了大量工作（aria-label、焦点循环、对比度 5.2–17.9:1），
  配色是唯一剩下的明显缺口。教学装置里「红=漂移、绿=好」的隐含判断对色觉障碍学生是丢失的信息。

### P3 · 长线 / 需评估

#### 2.12 姿态 → 位置：把闭环演示扩成一条 INS 叙事

- 项目已有闭环控制演示（用估计姿态驱动机体）。再往前一步是完整的捷联力学编排：
  姿态 → 把比力旋转到导航系并减去重力 → 速度 → 位置。
- **教学价值**：能直接展示误差阶数——陀螺零偏 b_g 造成的姿态误差 ~b_g·t，
  经重力投影变成加速度误差 ~g·b_g·t，速度 ~½g·b_g·t²，位置 ~⅙g·b_g·t³。
  **1° 倾角误差 ≈ 0.17 m/s² 水平加速度，几分钟内位置差出公里级**——
  这是「姿态解算精度为什么值钱」的量化答案。
- **出处**：死推算误差阶数与 GNSS/INS 融合见
  [Kok/Hol/Schön 综述 arXiv:1704.06053](https://arxiv.org/abs/1704.06053)；
  完整 INS 状态扩展（15 态加 p/v/加计零偏，24 态再加磁场/刻度/杆臂）见
  [Solà arXiv:1711.02508](https://ar5iv.labs.arxiv.org/html/1711.02508) §5–6。
- **成本**：高。3D 视图与全部 UI 都要容纳「位置」这一维，可能更适合做成**独立的第四个视图**或
  一个 2D 俯视漂移轨迹 inset，而不是改造主视图。

#### 2.13 经典姿态确定：Wahba / TRIAD / QUEST

- 在滤波之前，工程上还有一整类**确定性**姿态确定方法（用两组非共线向量观测直接解姿态）。
- **为什么值得**：本装置的「粗对准」其实就是 TRIAD 的退化形态（重力 + 磁，正交化）。
  把 TRIAD 讲清楚，粗对准就从「两个 atan2 公式」变成「有名字、有最优化背景的标准方法」；
  再接 Wahba 问题与 QUEST，就自然过渡到卡尔曼（「Wahba 是一次性最优解，卡尔曼是带时间记忆的最优解」）。
- **出处**：[Mayitzin/ahrs](https://raw.githubusercontent.com/Mayitzin/ahrs/master/README.md) 同时实现
  Mahony/Madgwick/EKF/UKF 与 Wahba/TRIAD/QUEST 全家族，可作为术语与实现参照。

#### 2.14 其它可选

- **Web Bluetooth 入口**：大量现成 IMU 模块是 BLE 的；比 Web Serial 覆盖面更广。
- **通用文本协议 / MAVLink 入口**：现在只认自制 28 字节二进制帧，用户必须自己刷固件才能接硬件。
  加一个「文本行模式」（`ax,ay,az,gx,gy,gz[,mx,my,mz]`，`\n` 分行）能接住绝大多数串口调试输出；
  再加 MAVLink `ATTITUDE`/`RAW_IMU` 解析就能直连飞控（PX4/ArduPilot）。
- **`src/main.ts` 拆分**：3403 行装配层。按 `docs`（约 700 行）、`serial`（约 250 行）、
  `charts`、`panels`、`sim` 切分，可在不改变运行语义的前提下大幅降低后续改动的心智负担。
- **图表的无障碍等价物**：三个 canvas 只有 `role="img"` + aria-label，没有数据表兜底。
  可给每个图表加一个「以表格查看当前数据」的可展开块（顺带成为截图/报告的素材）。
- **文档打印样式**：`@media print`，把文档页拉成可打印/存 PDF 的排版——教学装置的现实用法之一是发讲义。
- **公式复制**：`.formula` 块加「复制（Unicode / LaTeX）」按钮。

### 3.2 建议新增的模块（按价值排序）

#### ① 「万向节锁的算法后果」（作为 `filters` 或 `math` 的新章，或独立成页）

见 §2.1。内容骨架：机械面（环架轴重合）→ 数学面（欧拉参数化奇点，复用现有矩阵证据块）
→ **算法面（本装置实测曲线 + §1.1 的数字表）** → 结论（四元数为什么赢）。
这一章的主题句可以是：「万向节锁不是机械玩具的问题，是你的滤波器输出的问题。」

#### ② 「术语表与符号索引」（新模块）

- 全库术语/符号的字母序总表，每条 = 一句话定义 + 出处锚点链接（跳到定义它的章节）。
- 覆盖：四元数类（`q/−q/⊗/q̇/w,x,y,z/DCM/轴角/Slerp/Squad/log/exp`）、
  传感器类（比力/零偏/随机游走/Allan 方差/硬铁/软铁/磁倾角/磁偏角/量化 LSB/交叉轴/非线性）、
  算法类（互补/梯度下降/新息/协方差/可观性/门控/收敛/Wahba…）、坐标类（NED/FRD/ENU/ECEF/显示系）。
- **为什么**：文档现在 230 KB，同一符号在不同章反复出现（`δθ`、`eInt`、`b` 在不同语境含义不同），
  读者缺一个「回头查」的地方。与 ②「文档搜索」互补：搜索解决「找不到」，术语表解决「对不上」。

#### ③ 「排障手册」（新模块，或 `manual` 的第 10 节）

把三类排障合成一页决策树：
1. **曲线不对**——已有 `f-reading` 的 9 行表，直接收录并加「症状截图」；
2. **硬件接不上**——把 `firmware/README.md` 现有的排障表搬进应用内（波特率/接线/CRC 失败/丢帧统计读法）；
3. **页面本身异常**——SW 缓存旧页面、rAF 后台停摆、4173 端口占用（这些现在只活在
   `PROJECT-STATE.md` 的「已知坑」里，用户看不到）。

#### ④ 「参考文献与延伸阅读」（新模块）

- 应用内目前**零外链**（§1.4）。`RESEARCH-NOTES.md` 已有 47 条带出处的资源，只是没有进应用。
- 建议做成一张表：**文献 → 本装置哪一处与之对应**（例如「Letterman 式的 Mahony 实战增益 Kp≈1.5/Ki≈0.005」
  → d-algo 的 Kp 条目；「Solà ESKF 第 5 章」→ f-kalman-detail 第三步）。
- **为什么**：这是教学装置的学术可信度所在；也让「想深入的读者」有出口，
  而不是只能读到本装置的自述。

#### ⑤ 「练习与自测」（新模块）

- 每个知识点配 2–3 道题，**答案即一步实验**：题干给现象，要求在装置上复现并读出数字
  （例如「把零偏设为 3 °/s，纯积分曲线 10 s 后误差约多少？为什么是线性不是平方？」）。
- 复用现成的实验库机制（`ui/experiments.ts` 已是「参数快照 + 观察要点」的数据驱动结构），
  加一个 `question/answer` 字段就能生成「点击题目 → 一键装载参数 → 显示预期观察」的教学闭环。
- **为什么**：教师拿去做课堂任务、学生拿来自查；也是本项目「实验库」的自然延伸。

#### ⑥ 「学习路径 / 导览」（新模块或 `manual` 首页）

- 按背景给三条路线：**零基础**（快速上手 → 直觉章 → 控制项手册 → 曲线诊断）、
  **有信号处理/控制基础**（表示 → 积分推导 → 融合 → 卡尔曼推导页）、
  **只想接硬件**（坐标系约定 → 器件预设 → 磁校准 → 固件指南 → 排障）。
- 每条路线标注预计阅读时间与「读到这里应该能回答的问题」。
- 现在文档有「选读」徽标（5 处 `optional`），但**没有反向的推荐顺序**
  （`grep -c "学习路径\|阅读顺序"` = 0）。

#### ⑦ 「硬件与固件指南」（新模块）

- 把 `firmware/README.md`（协议表/接线/组帧/CRC/排障）搬进应用内，加上「本装置真实模式的语义」
  （为什么误差曲线改以 Mahony 为基准、为什么幻影隐藏、固件 tick 时钟的取舍）。

#### ⑧ 「关于 / 更新日志 / 致谢」（新模块或页脚弹层）

- 版本号、部署地址、技术栈、数据来源与口径声明、参考资料致谢、
  以及一份面向用户的**变更日志**（`PROJECT-STATE.md` 里有 12+ 个里程碑的详细记录，
  但那是开发者视图，用户看不到）。
- 顺带承载「本装置的简化与已知偏离」声明（磁偏角未模拟、MARG 为简化版、
  6 维 ESKF 是 24 态的姿态子集）——把可信度边界写在明处，是教学装置该有的诚实。

### 3.4 不建议做的

- **不建议把 `manual` 拆成多个模块**。控制项手册的价值在于「一个页面对照界面边读边调」，
  按面板再拆分反而增加跳转成本。新增内容应该做成**新模块**，而不是稀释现有模块。
- **不建议为「凑章节」加 UKF / 粒子滤波 / 因子图**。它们不在本装置的可演示范围内
  （没有可交互的现象可展示），写成文字章节会变成教科书摘抄，与「每个概念都能在装置上复现」
  的项目气质冲突。若要提，放在「滤波算法讲解」末尾作为一段**选型路线图**即可。
- **不建议把三个阶段（互补→Mahony→Madgwick）拆成三个视图**。同屏对比正是本装置的核心价值。
