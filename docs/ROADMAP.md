### 第三批：结构与发布收敛

## CI与执行授权边界

本次文档整理不提交、不推送、不触发远端任务。未来执行当前发布复核时：

1. 先获得授权，审阅需要提交的文件并提交改动，记录实际 SHA；不能只从 dirty 工作树建分支后直接 push，后者不会上传未提交代码。
2. 本地短轮通过后再运行已包含该提交的 workflow；确认当前 Windows 两片完整集合和实际 head_sha，不要求已范围外的跨平台。
3. 强化登记脚本后才登记 run/job/attempt 与报告 artifact；`current=true` 不得绕过来源检查。
4. 超时先记录为未完成或根因未知；没有诊断证据时，不把它直接归结为运行环境容量。
