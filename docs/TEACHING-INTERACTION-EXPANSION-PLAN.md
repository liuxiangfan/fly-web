## 执行模型交接说明

本文同时充当产品规格、技术设计和验收工单。接手实现的模型应按下面的方式使用它：

1. **先读项目级说明与当前状态**：根目录 `AGENTS.md`、`docs/PROJECT-STATE.md`、相关现有模块和测试；本文是扩展规格，不替代项目当前事实。
2. **先复现，再实现**：为当前缺失能力建立最小界面／数据反例。例如当前曲线游标只有数值、没有完整姿态回看；不能把它描述为已有回看。
3. **按阶段交付**：A→B→C→D→E，不一次性铺开所有 UI。每个阶段完成后留下可独立验收的版本。
4. **实现中可以调整模块名和内部接口，但不能自行放松教学与数值约束**。确有更简单实现时，说明替代方案、影响和验证，再采用。
5. **不得把计划标成已完成**：只有代码、永久测试、真实浏览器证据和对应文档全部落地后，才更新状态。
6. **不自行提交、推送、发布或触发远端工作流**；这些操作遵循项目授权边界。
7. **不擅自删功能、抬体积预算、延长超时或修改数值门槛**。遇到冲突时保留实测并报告。
8. **排除项不是待办**：不得加入约束选型、故障猜测评分、隐藏故障剧本或相关入口。
9. **不为了按计划写完而制造伪实现**：缺真实内部状态时宁可显示“未记录”，也不能用插值、默认零值或独立简化模型补齐。
10. **每一阶段都保留旧行为回归**：现有五算法、三视图、实验、课程、校准、INS、回放、批量、档案、导出与快捷键均不得被新任务流破坏。

## 0. 目标与范围

### 0.1 执行责任说明

本文把执行责任分成三类，避免“模型可以写代码”被误读成“模型可以独立签署全部教学与产品验收”：

| 标记 | 含义 | 可以形成的结论 |
|---|---|---|
| **M｜模型自主** | 模型可阅读代码、设计、实现、写测试、运行本地工具、修复并复核 | 代码和自动化证据已完成；结论不超过工具实际覆盖范围 |
| **H｜人工配合** | 需要人先作产品决策、提供环境／硬件或完成真实交互 | 未获得输入前，相关范围保持待决策／未测，模型不得自行替人决定 |
| **R｜人工复核** | 模型可准备材料和独立评审，但最终需要领域专家、教师、学习者或项目所有者确认 | 可形成“待人工复核”的候选结论，不能自动写成最终验收通过 |

M/H/R 是**工作责任**，不是能力等级。一个功能可以大部分为 M，同时仍有少量 H/R 门槛。例如模型能完整实现预测题和运行测试，但“题目是否适合目标学习者”仍需教学内容复核。

详细分工见附录 G；各阶段也列出最低人工配合项。默认原则是：

> **能由真实生产代码、可复现实验、自动化浏览器和明确规格证明的内容，模型自主完成并负责验证；需要改变需求、判断教学效果或代替真实用户体验的内容，必须保留人工边界。**

- 第 0～1 节：范围、排除项、教学与工程原则；

- 第 6～8 节：测试、风险与完成后的能力边界；
- 第 9 节：推荐的最小教学原型；
- 附录 A：模块边界和现有生产集成点；
- 附录 B：配置、Worker、预测、观测、事件、回看与 ESKF 数据契约；
- 附录 C：界面布局、空态／失败态、窄屏、焦点和等价文本；

- 附录 F：交付模板和下一接手者检查清单；
- 附录 G：模型自主、人工配合与人工核验矩阵。

本方案的目标不是继续增加算法或读数，而是把现有能力组织成下面的学习闭环：

```text
明确任务 → 作出预测 → 固定条件 → 改变一个变量 → 观察证据 → 解释原因 → 复盘验证
```

保留并纳入方案的方向：

1. **单变量对照台**：同一配置与种子，只改变一个明确的实验条件。
2. **预测—验证式学习**：先记录用户判断，再运行实验，最后对照预测、实测和解释。
3. **分轴误差与可观性解释**：区分倾角、偏航、观测接受状态和“当前没有修正”的原因。
4. **参数变化的直接反馈与当前任务上下文**：让用户随时知道改了什么、会发生什么、接下来做什么。
5. **事件时间轴**：把曲线上的变化与粗对准、门控、量程饱和、断流等事件关联起来。
6. **动画、曲线与历史回看联动**：从误差尖峰回到对应时刻的姿态、传感器输入和内部状态。
7. **ESKF 单步内部解剖**：在暂停时展示一个解算步的预测、观测、门控、修正和状态复位。
8. **按任务组织首屏入口和文档双向链接**：学习原理、做对照实验、自由探索各有清楚入口，教材可直接装载对应现场。

### 明确排除

本方案**不包含**以下两项，也不为其预留界面占位或评分逻辑：

- 从“算法哪个好”扩展为“给定算力／精度／动态约束时选哪个算法”的选型系统；
- 从“算法演示器”扩展为隐藏故障、让用户判断根因并评分的故障诊断训练器。

参数整定挑战继续保留，但不改造成上述任一系统。事件时间轴、证据联动和 ESKF 解剖只服务于**解释与复盘**，不自动生成故障诊断结论。

同样不在本方案内：用户账号、课程管理后台、积分排行、在线协作、完整飞控／PID 调参系统、新增一批没有新教学问题的估计算法。

## 1. 教学与工程原则

### 1.1 一次只回答一个教学问题

每个实验或练习必须写清四件事：

- **固定条件**：场景、种子、时长、解算频率、传感器配置和校准状态；
- **唯一变量**：本组对照唯一允许变化的条件；
- **观察证据**：指定曲线、读数、事件或内部状态；
- **可反驳的解释**：什么实测结果会支持或推翻当前解释。

“差异更大”“表现更好”不是充分教学目标；必须能指出具体证据。

### 1.2 不混淆执行路径

- 在线 A/B 是在当前连续仿真的两个估计器组之间比较；
- 本方案的对照台是**同一 runner 上两次独立、完整、可复现的运行**；
- 配置档案仍是 `restore: "config-only"`，不因增加对照报告而暗中恢复曲线或历史状态；
- 历史回看是只读查看已记录的状态，不接管实时仿真的时间轴；
- ESKF 解剖展示真实更新中采集的量，不在 UI 内重新计算一份“看起来相似”的滤波过程。

### 1.3 单一数值来源

继续复用 `SolveLoop`、`core/runner.ts`、现有估计器、校准链、种子和统计口径。禁止出现：

- 对照台专用简化算法；
- 文档入口专用参数映射；
- 课程专用积分器；
- UI 自己累计一套与 runner 不一致的 RMSE；
- 用 3D 动画插值冒充历史真实姿态。

### 1.4 离线优先与内存封顶

- 所有新功能在浏览器本地运行，不新增后端或账号依赖；
- 对照运行支持取消、重复启动和旧结果隔离；
- 历史帧、事件、对照曲线与 ESKF 诊断都设置容量上限；
- 非活动功能不持续记录高成本数据；历史回看和 ESKF 解剖不进入默认实时渲染热路径；
- 教材和任务入口保持键盘、窄屏、打印及等价文本可用。

### 1.5 计划数字与实测数字分开

本文中的阶段编号、任务数、目标容量是**设计约束**。上线前需要重新实测：

- 每项新增测试数量；
- 浏览器完整集合数量；
- 新增源码与构建产物体积；
- 交互延迟、运行取消、内存和长稳；
- 需要人工判定的视觉与读屏结果。

任何门槛不足或性能下降都先报告并评估，不通过删测试、抬预算或放宽阈值制造“阶段通过”。若交付内容与既有教学能力冲突，保留冲突并重新确定范围。

## 3. 总体功能模型

新增状态分成四层，避免所有功能继续堆进 `main.ts`：

| 层 | 职责 | 不得承担 |
|---|---|---|
| 实验定义 | 基线、变量、预测题、观察证据、解释、文档位置 | 直接修改 DOM 或运行仿真 |
| 对照运行 | 配置 patch、两次 runner 调用、取消、指标与曲线 | 在线 A/B 的实时调度 |
| 回看与诊断 | 有界历史帧、事件索引、只读游标、ESKF 步记录 | 改写真实运行状态 |
| 学习界面 | 当前任务、预测提交、结果对照、课程和文档导航 | 自己解释数值或重算算法 |

建议的数据对象如下。字段名是设计草案，实施时以最小必要集合落地：

```ts
interface ExperimentVariable {
  path: string;                 // 受白名单约束的配置字段路径
  label: string;
  a: unknown;
  b: unknown;
  unit?: string;
  affects: "sensor" | "estimator" | "schedule";
}

interface PredictionRecord {
  questionId: string;
  answer: string | number | string[];
  submittedAtIso: string;
  // 判断只针对该题已声明的证据；不把选择题包装成全面能力评分。
}

interface ComparisonResult {
  baseConfig: ExperimentConfig;
  variable: ExperimentVariable;
  a: HeadlessRunResult & { series: ErrorSeries[] };
  b: HeadlessRunResult & { series: ErrorSeries[] };
  completed: boolean;
}

interface ReviewFrame {
  runId: number;
  t: number;
  truthQ: Quat;
  estimateQ: Quat;
  raw: ImuSample;
  consumed: { accel: V3; mag: V3 };
  telemetry: EstimatorTelemetry;
  error: { totalDeg: number; tiltDeg: number; yawDeg: number };
}
```

要求：

- 配置 patch 只能由白名单生成，不接受任意路径写入；
- 同一 `ComparisonResult` 的 A/B 除变量字段外，规范化配置必须逐项相等；
- 两次运行都实际完成后才标记 `completed=true`；
- 回看帧的 `runId` 不匹配时不得显示；
- 无真值或缺内部状态的帧显式显示“不可计算／未记录”，不补零；
- 所有展示文本来自受控模板，实验说明如允许 HTML，继续限制为既有白名单内联标签。

## 4. 分项详细设计

### F-01 单变量对照台

#### 教学目标

用户能够区分“同一输入下某变量的影响”和“两次随机运行碰巧不同”，并用 RMSE、峰值、收敛时间及事件证据支持结论。

#### 用户流程

1. 从实验库选择支持对照的实验，或在当前模拟配置点“创建对照”。
2. 系统冻结一份规范形基线配置，显示场景、种子、时长、解算频率、校准应用状态。
3. 用户从该实验允许的变量中选择一个；默认给出 A=基线、B=变化值。
4. 系统实时展示完整配置差异；存在额外差异时禁止开始，并指出字段路径。
5. 点击“运行对照”，A、B 通过同一异步 runner 分别完整运行。
6. 展示双侧曲线和统一指标表，提供“交换 A/B”“恢复基线”“再次运行”“导出报告”。
7. 返回实时模拟时保留对照结果，但不把对照的某一侧暗中写回实时控件；只有点“将 B 应用到装置”才显式应用。

#### 首批变量

首批只做能覆盖不同机制的五类，不开放任意参数自由组合：

| 实验 | A → B | 主要证据 |
|---|---|---|
| 方向门控救场 | 方向门控关 → 开 | 总误差、拒绝事件、观测接受率 |
| 磁干扰与偏航 | 磁修正关 → 开 | SO(3) 偏航误差、磁接受状态 |
| 解算频率 | 500 Hz → 50 Hz | 误差序列、实际解算步数、终止时刻 |
| 传感器群延迟 | 0 ms → 25 ms | 纯积分误差、机动时刻的原始输入 |
| 卡尔曼 Q/R 调参 | 基线 Q/R → 指定候选 Q/R | 稳态 RMSE、零偏估计、NIS/NEES（适用时） |

其中磁开关必须明确作用域：如果当前配置是“五算法各自开关”，对照变量只能修改选定算法；若语义是全局广播，则界面必须显示“此变量会改变全部适用算法”，不允许差异检查漏报。

#### 实现步骤

1. 在 `core/` 增加纯函数模块：配置字段路径解析、受控 patch、递归差异和变量描述。
2. patch 通过 `cloneExperimentConfig` 创建候选，再走现有校验／规范化；原配置不可被修改。
3. 在 `core/batch-protocol.ts` 定义独立 `comparison` 任务，或新增专用 comparison worker 协议；不复用 `batch.start` 的消息字段假装支持曲线。
4. Worker 顺序执行 A、B，复用 `runExperimentDetailedAsync`；每个侧只回传本方案需要的序列、事件和指标，不回传未使用的重数据。
5. 主线程保存 `jobId`、运行代次与任务来源；取消、重启、页面销毁和旧 Worker 晚到结果不得污染新任务。
6. 主线程降级路径也调用同一异步详细 runner，并沿用分片让出与取消语义。
7. 对照图采用同一时间范围、相同纵轴单位；误差图默认同一纵轴范围，自动缩放时明确标注。
8. 指标差值统一为 `B − A`，收敛时间一侧未收敛时显示“未收敛”，不得把 `null` 算成 0。
9. 报告导出使用新文件类型和 schema，明确包含两次完整配置、种子、变量、指标、事件与构建信息；不改变现有配置档案的 `config-only` 含义。
10. 初版导出只包含摘要与配置，不默认导出全部逐点曲线；若后续加入曲线导出，单独定义容量与 schema。

#### 永久反例与测试

- 只有声明变量不同，A/B 其他字段逐项相同；
- 修改未知路径、嵌套原型键、非法数值和未表达校准模型均受控拒绝；
- 种子、时长、粗对准、校准状态不能因建组而漂移；
- A/B 与单独调用同一 runner 的逐点结果一致；
- 交换 A/B 后差值符号反转，曲线身份不串；
- 任一侧被取消时整个对照不标完成、不生成“最终结论”；
- 连续开始两个对照，只接受新 `jobId`；
- 无样本、未收敛、非有限值正确显示，不变成 0；
- 真实 IMU／无真值回放不提供依赖真值的误差对照，界面解释原因。

### F-02 预测—验证式学习

#### 教学目标

把“读观察要点”改成“先暴露自己的模型，再用证据修正”。不以选择题得分替代理解，也不要求用户写出数值精确答案。

#### 用户流程

1. 进入支持预测的课程步或实验，先看到场景和固定条件，**默认不显示答案与观察结论**。
2. 完成预测：可以是数值范围、曲线趋势或可选机制。
3. 提交后锁定该次预测原文，显示“已记录预测”，提供运行按钮。
4. 运行单组或对照实验；未完成前不展示答案。
5. 结果页并排显示“我的预测 / 实际证据 / 解释”，并列出应看的曲线、指标或事件。
6. 用户可写一句“我修正后的理解”，再运行同一实验或进入下一题。
7. 提供“查看原预测”和“重新挑战”；重新挑战创建新记录，不覆盖上一次。

#### 首批练习

优先将现有文档中 12 道练习里的 **5 道**转为可执行练习，不一次迁移全部题目：

1. 零偏 × 时间的线性漂移；
2. 加计能修倾角但不能单独修偏航；
3. Mahony 中 Ki 对恒定零偏的作用；
4. 万向节锁时不同横滚／偏航组合得到同一姿态；
5. 群延迟造成约 `ω·τ` 的动态误差。

每题先定义可验证证据，再写答案。不能用“选择 A”这种脱离运行结果的伪交互。

#### 实现步骤

1. 在 `ui/` 建立学习活动纯数据定义：`question → evidence → explanation → experiment/comparison → doc anchor`。
2. 预测类型先支持单选、多选和数值范围三种；数值题不要求逐位相等，按预先声明的合理区间判断“符合／不符合预测”。
3. 会话状态只存当前页面内的题目、预测、对应运行 ID 和结果；刷新后不宣称保留进度。
4. 将 F-01 的结果适配为证据视图；不依赖对照的题直接复用现有实时实验或 runner。
5. 答案解释只在结果就绪后显示；查看教材提示不自动判为完成。
6. “重新挑战”明确是否沿用种子：首轮复习沿用同一种子，变式题再改变一个已声明条件。
7. 导出学习记录使用独立 JSON，包含问题版本、原预测、证据摘要和反思文本；不包含个人信息，不默认上传。
8. 原 13 步课程继续作为快速导览；新增“预测式学习路径”，不强迫现有用户改变入口。

#### 永久反例与测试

- 未提交预测时运行按钮可预览现场，但不能显示“预测结果对照”；
- 提交后运行失败／取消，原预测仍在，答案不错误解锁；
- 结果与问题 ID、运行 ID 不匹配时拒绝绑定；
- 数值空输入、NaN、超范围不进入判断；
- 多选采用明确的全对或逐项反馈口径，不把部分命中包装为全对；
- 用户反思按纯文本渲染，`<script>` 等内容不得注入；
- 重开课程不串用上题答案；
- 预测记录导出不含隐式设备信息。

### F-03 分轴误差与可观性解释

#### 教学目标

把“总误差是多少”拆成“误差在哪个自由度、当前有没有观测能修它、本帧实际有没有应用修正”。

#### 展示内容

在模拟模式新增可折叠“误差来源与可观性”面板：

- 当前算法的 SO(3) 倾角误差、绕世界重力轴的偏航误差和总误差；
- 加计观测：有效／无效、通过／拒绝、拒绝原因；
- 磁观测：启用／停用、有效／无效、通过／拒绝；
- 当前修正状态：已应用／未应用／仅预测；
- 当前教学解释及对应文档入口。

可观性文案采用**保守状态描述**：

```text
重力观测已应用：对倾角提供约束；绕重力轴的旋转仍无重力信息。
磁观测未启用：本算法当前没有来自磁场的偏航修正。
观测被拒绝：本步没有应用这项修正；不据此声称系统永久不可观。
```

禁止把一步拒绝写成“系统已经不可观”，也禁止仅凭校准残差或误差大小自动判断故障原因。

这里还需区分三个层次：

1. **几何约束**：重力向量本身不携带绕重力轴旋转的信息；这是可以直接解释的几何事实。
2. **当前算法通道**：磁修正关闭、观测被拒绝、估计器没有使用该通道；这是当前实现的实际状态。
3. **完整系统可观性**：与机动、历史激励、状态模型、噪声和时间窗口有关，不能由一帧遥测给出充分证明。

因此本功能默认只展示前两层。不要用“局部可观／不可观”给整个滤波系统下结论；如果后续要讲完整可观性，应另写教学内容并明确其适用条件。

#### 实现步骤

1. 在 `core/` 提取分轴误差纯函数或复用 `so3ErrorSplit`，输入为明确的 `q_truth ⊗ q_est⁻¹`；固定世界 NED 重力轴 `[0,0,1]`。注意该函数本身只返回倾角／偏航**幅值**；若界面要有符号分轴方向，应另外定义旋转向量分量，不能给幅值擅自加符号。
2. 在 `SolveLoop.onSolve` 的同一子步读取姿态与估计器遥测，生成一个展示快照；不在下一帧拼接不同时刻的量。现有 `onSolveDefault` 在静止粗对准发生后执行，因此快照中的姿态必须明确是“本步更新并完成可能发生的粗对准之后”的状态；若要展示粗对准前状态，需要另取 `onAlign` 中的真实数据，不能用前者反推。
3. 为 `EstimatorTelemetry` 补充最小必要的“本帧修正是否应用”与拒绝原因；无法统一语义的算法提供明确状态，不填造默认值。
4. 面板默认只显示当前主视图算法，允许切换到其他算法；切换只改变展示对象，不改运行配置。
5. 显示倾角、偏航和总误差三条曲线时，默认仍突出总误差，避免新增曲线淹没主图。
6. 与 F-05 的时间轴共享观测接受状态；与 F-06 的回看帧共享同一份快照结构。
7. 无外部真值时显示“无真值，误差分量不可计算”，仍可观测试接受状态，但不把 Mahony 基准称作真值。

#### 永久反例与测试

- 纯偏航误差：tilt≈0、yaw 等于设定值；
- 纯倾角误差：yaw≈0；
- 万向节锁邻域不发生欧拉角分解式跳变；
- 倾斜姿态下世界系／机体系误差不可互换；
- 加计有效但被门控拒绝时，必须显示“有效、未应用”，不能显示“已修正”；
- 磁关闭与磁测量退化是两种状态；
- 纯积分的“未应用观测修正”不得显示成门控故障；
- 无真值、零模长、非有限输入均不生成虚假可观性结论。

### F-04 参数反馈与当前任务上下文

#### 教学目标

降低用户在 24 个以上控件中迷失的成本，让每次操作都回答“改了什么、影响哪里、是否重置、下一步是什么”。

#### 参数反馈

每次用户提交参数变化后，在对应控件附近和轻量提示区显示：

```text
解算频率：500 → 50 Hz
影响：估计器每 20 ms 更新；底层仿真仍为 500 Hz
本轮处理：已重置仿真 / 从当前状态继续（按真实行为）
建议观察：姿态总误差与解算事件
```

在主视图上缘或右侧控制台顶部显示可收起任务条：

- 当前实验／课程／自由探索；
- 固定条件和当前唯一变量；
- 观察目标；
- 下一步动作；
- “退出任务，回到自由探索”。

任务条不覆盖现有视图切换和读数；窄屏只保留标题、当前步骤与展开按钮。

#### 实现步骤

1. 建立控件元数据表：控件 ID、配置字段路径、物理单位、影响层、是否触发重置、观察建议和文档位置。
2. 元数据必须覆盖所有新增反馈的控件；未登记的旧控件保持现有行为，不伪造说明。

4. 实验装载只产生一条聚合反馈，不连续弹出几十条滑块提示。

6. 对运行期持续拖动做合并反馈，避免高频 toast；数值输入、键盘与滑块走同一出口。
7. 当前任务来自实验／课程／对照的统一 `TaskContext`；自由探索不强行生成任务。
8. 修改参数后，若原实验的唯一变量已被改变，任务条显示“已偏离原实验”，而不是继续宣称正在做原始对照。
9. 真实 IMU／回放模式下，被停用的模拟参数给出原因，不显示“已影响仿真”。

#### 永久反例与测试

- 拖动、键盘、数值框、实验装载都能正确显示最终生效值；
- 程序初始化不制造用户修改提示；
- 一次实验装载只有一条聚合消息；
- 真实模式停用控件不出现虚假反馈；
- 修改非变量参数能退出“严格单变量对照”状态；
- 重置语义必须与实际 `resetSim()` 调用一致；
- 任务退出只清学习上下文，不擅自清曲线或改实验参数。

### F-05 事件时间轴

#### 教学目标

将“曲线为什么在这里变化”连接到“同一时刻系统发生了什么”，支持按事件复盘，而不是继续增加静态读数。

#### 首批事件

| 类别 | 事件 | 数据来源 |
|---|---|---|
| 解算调度 | 粗对准发生、运行重置、暂停／继续 | `SolveLoop` 与真实界面动作 |
| 观测 | 加计拒绝开始／结束、恢复窗开始／结束、卡尔曼门控原因 | 估计器遥测，按状态边沿记录 |
| 器件 | 陀螺量程饱和开始／结束 | 传感器模型的真实饱和状态；当前 `simulateImu` 只输出削顶后的样本、尚无显式饱和事件，需在真正削顶的分支附加只读观测信号 |
| 数据 | 断流开始／恢复、重连尝试／成功／耗尽 | 数据源与重连状态机 |
| 学习操作 | 参数改变、实验装载、视图切换 | F-04 的真实动作出口 |

“事件”使用仿真／数据时间作为主轴，同时可保留墙钟时间用于诊断；两者不能混写。

饱和事件必须在传感器实际执行削顶的位置产生；当前仅有削顶后的 `ImuSample`，没有现成饱和事件。若不愿扩展该观测接口，首版应把饱和标为“未接入”，不能用 `abs(gyro)≈range` 或姿态误差在 UI 中猜测饱和。新增诊断观测不得改变随机数消耗、样本数值、更新次序或真值；字段应可选，避免破坏既有 `ImuSample` 透传逐位一致契约。

#### 交互

- 曲线顶部增加紧凑轨道，使用图形＋文字列表，不只靠颜色区分；
- 点击事件定位共享游标，显示前后状态和证据；
- 支持“上一事件／下一事件”与类别过滤；
- 键盘可遍历事件；
- 超出保留窗口后明确显示已裁剪数量；
- 暂停／继续本身不能制造重复观测拒绝事件。

#### 实现步骤

1. 定义统一 `LearningEvent`：`runId/t/type/estimator/summary/before/after`。
2. 观测和饱和类事件从状态**边沿**产生；原始逐帧拒绝计数保留，但不把 500 Hz 每一帧都变成一条 UI 记录。
3. 参数事件记录最终生效值和配置字段路径，不存 DOM 节点。
4. 使用固定容量环形缓冲，容量与采样策略写入诊断；超出时淘汰最旧事件并累计 dropped 数。
5. 曲线游标定位到事件对应的真实时间；若没有精确历史姿态，只显示“曲线位置”，不能承诺 3D 回看。
6. 事件详情与 F-03 共用状态说明，与 F-06 共用回看帧索引。
7. 数据源切换、重置、导入、任务切换必须更新 `runId`，旧事件不能落到新轮。
8. 打印和等价文本提供事件列表，不要求读屏解析 Canvas 图形。

#### 永久反例与测试

- 连续拒绝 100 帧只形成“开始／结束”一对边沿事件；
- 恢复窗与粗对准不会在 UI 和 runner 各记一次重复事件；
- 饱和需要来自真实削顶状态，不用误差大小猜测；
- 重置后旧 `runId` 事件不可点击或污染新时间轴；
- 空窗、同一时刻多事件、非有限时间有确定处理；
- 容量达到上限后长度不增长，淘汰计数准确；
- 鼠标、键盘和等价文本选中的是同一事件。

### F-06 动画、曲线与历史回看联动

#### 教学目标

从历史误差尖峰返回当时真实姿态、传感器输入和估计器状态，进行逐事件复盘。

#### 两种模式必须分清

- **查看模式**：当前曲线游标只读最近数值；没有姿态快照时显示“仅曲线读数”。
- **回看模式**：存在真实 `ReviewFrame` 时，3D、曲线、IMU、分轴误差和内部状态都指向同一帧。

回看不是将实时仿真倒带，也不从当前状态反向积分。实时仿真在后台继续时，界面必须显示“正在回看历史 · 实时已推进到 t=…”；恢复实时后才重新显示最新状态。

#### 实现步骤

1. 在 `onSolve` 按显示记录频率保存 `ReviewFrame`，与曲线采样使用同一时钟和允许误差。
2. 初版建议记录频率不超过曲线记录频率（约 25 Hz），时长先与当前 30 秒曲线窗口一致；容量以实测为准，不把高频全量状态常驻内存。
3. 仅在用户开启“历史回看”或进入支持回看的任务后记录；默认实时模式不增加高成本快照。
4. 帧包含真值与当前算法姿态、源输入、实际消费输入、遥测、误差分量和 runId；ESKF 大矩阵只在 F-07 启用后另外采样。
5. 暂停时拖动或键盘移动游标，找到最近历史帧并显示实际时间差；超过容差时显示“该时刻无回看帧”。
6. 回看帧驱动现有 3D 姿态渲染的只读输入；不得写回 `ests[i].q`、`world.q` 或 INS 状态。
7. 点击误差尖峰／事件时定位同一帧，并高亮对应的原始陀螺、加计和磁读数。
8. 提供“返回实时”“上一帧／下一帧”“回到事件前／后”。
9. 重置、导入档案、换源和开始新对照时清空或封存旧帧，旧帧显示所属运行，不混入新轮。
10. 记录存储采用定长缓冲；评估 typed array／结构化快照的成本，避免每帧无界对象分配。

#### 永久反例与测试

- 回看不能改变实时世界、估计器、统计、INS 或录制内容；
- 从任一历史帧返回实时后，显示最新真实状态而非从旧状态续跑；
- 曲线游标、3D 姿态、IMU 和遥测来自同一 `runId/t`；
- 两个相邻帧不能串用前一帧遥测；
- 回看暂停／继续／重置／换源后状态明确；
- 无快照时只显示曲线读数，不伪造模型姿态；
- 容量、时间和帧数上限都实测，长稳不增加无界内存。

### F-07 ESKF 单步内部解剖

#### 教学目标

让用户理解一个真实 ESKF 更新步中，预测、观测、门控、增益、误差注入和协方差变化的关系，而不是只背 `Q/R/K/P` 名称。

#### 展示步骤

仅在**已暂停的当前解算步、单步推进后的当前步，或存在真实 ESKF 诊断快照的历史回看帧**中展开。仅暂停但没有对当前步采集诊断快照时，应显示“当前步未记录内部快照”，可引导用户单步采集；不能用下一帧数据补当前空缺。

```text
① 更新前：q、零偏 b、P
② 预测：修正后的陀螺 ω−b、预测姿态、P⁻
③ 观测：预测重力／磁方向、实测方向、新息
④ 判定：门控类型、阈值、接受或拒绝原因
⑤ 更新：S、K、误差状态 δx
⑥ 注入：q、零偏 b、P 的实际变化
⑦ 复位：是否执行可选协方差重置
```

默认显示向量、对角方差和关键标量；完整 6×6 矩阵放在“展开矩阵”内。每一步同时给出单位、坐标系和“这一步真正改了什么”。

#### 实现步骤

1. 为 `KalmanEstimator` 定义只读诊断快照，不把私有 `P` 可变引用暴露给 UI。
2. 在 `update()` 内设置诊断采集器／回调；未启用时走原有路径，不增加每帧大对象分配。
3. 快照必须来自同一个 `update()`：更新前状态、预测后状态、各观测更新、注入后状态不可跨帧拼接。
4. 加计与磁更新分开记录，因为一次 `update()` 可能连续应用两次观测；不能把最终 K 当作两次共用增益。
5. 对 `S` 奇异、门控拒绝、退化输入、零 dt 等情况记录真实原因，缺数据用 `null` 表示。
6. 显示误差注入前后姿态差、零偏差和 P 对角变化，明确姿态误差状态与世界／机体系约定。
7. 可选的 `P ← GPGᵀ` 只有在配置实际开启时才显示“已执行”；关闭时写“未启用”，不是省略这一步的存在。
8. 历史回看只在用户选择 ESKF 诊断并开启记录时保存快照，设置独立小容量上限。
9. 数值显示与估计器使用同一单位源；rad、°、rad/s、°/s 在标签中写清。
10. 加入文档“本步发生了什么”入口，链接到现有 ESKF 推导对应章节。

#### 永久反例与测试

- 采集关闭时，原姿态、零偏、协方差与完整结果逐位不变；
- 采集开启只读观察，不改变更新次序和数值；
- 零观测修正时姿态只由预测推进；
- 加计与磁均接受时，存在两条有顺序的更新记录；
- 门控拒绝时没有虚假的 K／δx 已应用记录；
- `S` 奇异返回未更新，不把 NaN 显示为 0；
- 零偏限幅、P 对称化、可选重置按真实执行状态显示；
- 回看快照与生产 `neesAgainst()`、姿态和遥测可交叉核对。

### F-08 任务式入口与教材双向链接

#### 教学目标

降低首屏认知负担，让用户按学习目标进入，而不是先理解所有面板；教材中的结论可以直接变成可复现现场。

#### 首屏入口

保留现有完整界面，在首次使用或用户主动打开“学习路径”时提供三个入口：

```text
我想学原理 → 概念路径 / 预测式课程
我想做实验 → 实验库 / 单变量对照台
我想自由探索 → 当前完整装置
```

“导入 IMU 日志”继续放在数据源区，不包装成被排除的故障诊断训练器。入口只是导航，不新增三类应用或三套状态。

#### 教材双向链接

重要结论旁按内容提供：

- **运行这个结论**：装载固定实验；
- **查看反例**：装载一个能推翻过强结论的对照；
- **先预测再运行**：进入 F-02 活动；
- **返回阅读位置**：返回原页面与章节。

每个可执行结论声明 `claimId`、实验／对照 ID、变量、证据和文档锚点。未定义证据的结论不强行加按钮。

#### 实现步骤

1. 用纯数据定义学习路径与入口，不复制课程内容；继续引用实验 ID 和文档锚点。
2. 首屏默认仍展示装置，轻量入口可收起；避免每次打开都强制模态欢迎页。
3. 当前任务条复用 F-04；从文档打开实验后保留来源页和滚动位置。
4. 文档打开使用既有模态与焦点管理，不让自动打开的文档盖住课程“下一步”。
5. 返回时恢复文档页、章节和焦点；若文档从未打开过，不生成虚假返回位置。
6. 实验／配置在文档跳转期间若已改变，显示“当前现场已偏离该结论”，提供显式重新装载。
7. 教材新增按钮使用纯文本或受控模板；所有 `claimId`、实验 ID 和锚点由静态检查验证。
8. 窄屏入口垂直排列，键盘焦点顺序与视觉顺序一致；打印默认不打印操作按钮。

#### 永久反例与测试

- 三个入口都能用键盘进入、退出并回到合理焦点；
- 运行结论后场景、变量和观察证据与声明一致；
- 文档锚点、实验 ID、对照 ID 不存在时构建检查失败；
- 文档→装置→文档往返恢复原章节与阅读位置；
- 用户改过参数后不继续冒充原结论现场；
- 首屏入口不遮挡运行控制，不反复自动弹出；
- 320／390／768／1440 视口和 200% 页面缩放无横向溢出或关键按钮丢失。

**模型可自主完成**：回看缓冲与只读渲染、ESKF 诊断快照插桩、逐位等价契约、容量与资源测量、长稳与浏览器回归。

## 7. 风险与取舍

| 风险 | 后果 | 控制方法 |
|---|---|---|
| 对照被误当成在线 A/B | 固定条件与统计结论失真 | 明示两次独立运行，配置 diff 和 runner 对拍 |
| 新增曲线、事件和面板过多 | 认知负担反而上升 | 当前任务只显示必要证据，高级信息折叠 |
| 可观性文案过强 | 把一步拒绝误讲成永久不可观 | 只描述当前信息／修正状态，使用保守模板 |
| 回看写入实时状态 | 污染仿真、记录与统计 | 独立只读快照，禁止写回 world/ests/INS |
| ESKF 诊断采集改变算法 | 教学观察工具影响被观察对象 | 默认关闭、快照只读、逐位等价契约 |
| 大快照和曲线回传失控 | 内存、Worker 传输和主线程压力 | 按需记录、定长缓冲、只传必要字段、实测前后对照 |
| 文档按钮与实验漂移 | 用户运行了错误现场 | claim 映射、静态 ID 检查、偏离提示 |
| 预测功能变成答题游戏 | 记答案而非理解证据 | 强制展示原预测、实际证据和解释，不做排行 |
| 阶段范围不断扩大 | 长期停留在半成品 | 每阶段冻结首批内容；排除项不得借后续阶段回流 |
| 体积或性能预算过紧 | 新功能不能安全合入 | 先原型测量再定实现；需要改变门槛时另行决策 |

## 8. 完成后的能力边界

即使全部阶段验收通过，本装置仍只证明其实际覆盖的教学场景：

- 它是四元数姿态解算与传感器误差的学习装置，不是自动选型器；
- 它不是故障诊断训练器，事件解释不等于自动根因判断；
- 仿真／mock 结果不替代真实硬件结论；
- 预测题结果不替代系统的学习成效评估；
- 历史回看只覆盖实际保存的帧，不是任意时长完整状态数据库；
- ESKF 解剖解释当前实现，不自动代表所有 ESKF 变体；
- 文档中的每个定量结论仍需由当时构建上的实验／基准支持。

## 9. 推荐首个原型

### 方案定位

本方案描述完整目标架构，但不要求在一个 PR／一次会话内全部实现。正式实施的默认顺序是第 5 节 A→E；本节原型用于在投入完整建设前，以最小范围检验教学设计是否成立。

### 范围与依赖

原型跨越 A／B／C 的少量能力，是**有意的教学验证切片，不代表这些阶段已验收**：

- 来自 A：单变量配置、两次真实运行、对照指标和结果报告；
- 来自 B：一条预测记录与预测—证据—解释对照；
- 来自 C：一个真实的门控拒绝事件；
- 不包含：F-04 全量任务条、F-06 历史回看、F-07 ESKF 快照、F-08 全站入口。

事件只要求说明“t 时发生了什么”，不要求定位完整 3D 姿态。若原型必须先完成阶段 A 才能开始，可将本原型作为 A 完成后的首个跨功能集成验证，而不是绕过阶段 A 的生产契约。

### 原型用户路径

若要验证本方案是否值得全部投入，先做一个最小但完整的原型：

> **“方向门控开／关”单变量对照 + 一条预测题 + 一个拒绝事件。**

完整路径：

```text
固定协调转弯配置与种子
→ 预测“打开方向门控后，倾角误差和观测接受率会怎样”
→ 记录预测
→ 分别运行门控关／开
→ 对照误差曲线与接受率
→ 点击拒绝开始事件
→ 解释“污染被阻挡，但持续拒绝也意味着失去该项修正”
→ 返回原文档章节
```

这个原型能同时验证配置契约、runner 复用、预测绑定、事件真实性和教材导航，却不需要先建设历史回看或 ESKF 大快照。原型验收通过后，再按阶段 A→E 扩展；若发现对照结果难以解释或界面更复杂，应先修正模型，而不是继续堆功能。

### 现有代码中必须复用的出口

1. **实验装载**：沿用 `applyExperiment()` 的基线复位和真实控件路径，不从课程或教材写第二套 setter。
2. **实时配置**：对照基线使用 `currentExperimentConfig(durationSec)`，不要从局部控件拼凑缺少校准／粗对准的配置。`ab` 的 `online-fork/same-start` 是界面执行方式，runner 不消费；对照两侧必须固定相同展示执行语义，不能让它偷偷成为第二变量。
3. **实际消费输入**：快照使用 `onSolveDefault()` 收到的 `ctx.sample / ctx.accel / ctx.mag`，不能在记录时拿“当前校准”重新计算历史输入。
4. **共享调度**：继续从 `SolveLoop.onSolve/onAlign/onFrame` 获取解算与事件，不绕过待积分队列。现有 `SolveLoop.setHooks()` 只替换提供的回调；临时 trace 路径会在内部调用 `onSolveDefault`。新增事件／回看采集应设计为附加观察器或统一回调组合，不得在替换 hook 时丢失 INS、消费快照、课程或其他生产副作用，也不要求每个调用方重复补一遍。
5. **误差参考**：使用 `currentReferenceKind()` 和当时真实参考，不将 Mahony 基准当作 ground truth。回放有外部真值时必须在 `onSolveDefault` 对应子步调用 `replayTruth.at(ctx.t)` 后再取值；不能拿帧末真值。
6. **场景渲染**：给场景一个明确的展示四元数来源；回看只替换展示输入，不替换真实估计器对象。万向节和四元数页有独立演示状态，回看联动首先限定在四轴姿态视图；其他视图需要回看时另行定义展示对象，不把姿态帧硬套到独立演示动画。
7. **文档焦点**：复用 `setDocsOpen()`、`showDocPage()`、`docScrollMemory` 和 `docsPrevFocus`，不并行实现第二套模态焦点。
8. **导出下载**：复用现有 Blob／下载出口；不同档案类型通过各自 schema 区分。
9. **自动化**：扩展现有浏览器冒烟和清单，不写一个只在开发服务器上成立的平行测试应用。

### 避免扩大主装配文件

阶段 A 开始前，不必先完成全部既有 SW-12 重构，但至少做到：

- 新对照、预测、事件和回看的状态不定义成 `main.ts` 的大量松散变量；
- 每项状态的转移有可独立测试的纯模块；
- DOM 入口只做输入读取、调用服务、呈现返回结果；
- 不把新 UI 的全部 HTML 字符串和业务判断集中塞到 `main.ts`；
- 如果必须修改现有批量任务以复用生命周期，先把相关控制流抽成共享模块，并保留现有取消回归。

# 附录 B：核心数据与协议契约

以下接口比正文更接近实现细节，但仍是**设计草案**：实现者可以减少字段、拆分文件或调整命名；不可丢失字段所表达的来源、时间和缺失语义。

## B.1 配置变量与 patch

推荐用声明式 setter 描述变量，而不是提供通用的字符串路径写入器：

```ts
type ComparisonVariable =
  | { kind: "accel-gate"; estimator: "comp" | "mahony" | "madg"; a: boolean; b: boolean }
  | { kind: "mag-enabled"; estimator: "comp" | "mahony" | "madg" | "kalman"; a: boolean; b: boolean }
  | { kind: "solve-rate"; a: number; b: number }
  | { kind: "sensor-delay"; aMs: number; bMs: number }
  | { kind: "kalman-noise"; a: { gyroNoiseDps: number; obsNoise: number }; b: { gyroNoiseDps: number; obsNoise: number } };
```

理由：类型化联合比任意 `path: string` 更容易保证白名单、安全、单位与 UI 可表达性。若仍采用路径 patch：

- 只接受显式白名单里的完整路径；
- 拒绝 `__proto__`、`prototype`、`constructor` 和任意容器替换；
- 数字必须有限，枚举必须合法，数组必须完整深拷贝；
- patch 后重新做完整配置校验，而不是只校验新值；
- 得到合法配置后再规范化，用于差异比较；
- 不允许 patch `seed/durationSec/scenario` 充当“唯一变量”；这些属于固定条件，修改时应另建对照任务。

`kalman-noise` 在教学上是一组协同变量，不是一个“严格只有一个字段变化”的对照。因此有两种允许做法：

1. 首批只改 `obsNoise`，固定 `gyroNoiseDps`；或
2. 明确命名为“Q/R 参数组对照”，说明它研究的是相对信任关系，不声称是单字段因果实验。

不得一边改 Q 和 R，一边将界面写成“只改变一个参数”。

## B.2 对照运行协议

建议独立于现有批量协议，因为结果形状、进度与资源成本不同：

```ts
type ComparisonRequest =
  | { type: "start"; jobId: number; base: ExperimentConfig; variable: ComparisonVariable }
  | { type: "cancel"; jobId: number };

type ComparisonSide = {
  config: ExperimentConfig;
  metrics: EstimatorRunMetrics[];
  series: ErrorSeries[];
  events: RunEvent[];
  finalQuats: Record<EstimatorId, Quat>;
  termination: RunTermination;
};

type ComparisonResponse =
  | { type: "phase"; jobId: number; side: "a" | "b"; phase: "running" | "summarizing" }
  | { type: "progress"; jobId: number; side: "a" | "b"; simulationSec: number; durationSec: number }
  | { type: "side-complete"; jobId: number; side: "a" | "b"; result: ComparisonSide }
  | { type: "done"; jobId: number; a: ComparisonSide; b: ComparisonSide }
  | { type: "cancelled"; jobId: number; completedSides: number }
  | { type: "error"; jobId: number; side: "a" | "b" | null; message: string };
```

若为了简化只保留最终 `done`，也必须提供进度、取消和错误语义；不能让用户只能等待整批结束。

### 运行规则

1. 在 Worker 内先构造 A/B 配置并再次检查唯一差异，不信任主线程声明。
2. 默认顺序 A 后 B；同一 job 内两边使用相同 runner 版本、同一初始种子、同一终止条件。
3. 每侧完成后先冻结／复制所需数据，再开始下一侧；不能让后续估计器复用修改前侧对象。
4. A 完成、B 未完成时显示“A 已完成，B 进行中”，不显示对照差值或最终结论。
5. 取消时返回真实 `completedSides`，但 UI 不生成最终对照报告；用户可选择查看未完成数据，其状态必须标未完成。
6. 任一侧 `termination.reason !== "completed"` 时，整个对照不是完整完成。
7. 两侧时间窗、样本窗口、统计截断状态和事件保留范围要显示；若不同，不做误导性的逐点差。
8. Worker 出错只触发当前 job 的受控降级；旧 job 的错误不能触发新 job 的主线程运行。
9. 主线程降级复用异步详细 runner、分片预算与 generation；不得在 A 或 B 内一次性同步跑完。
10. 离开页面对照视图不自动取消计算；只有用户取消、新任务替代或显式清理才停止，并在返回时恢复真实进度。

### 数据传输与内存

- 对照曲线初版只保留任务要求的算法和序列；如实验观察五算法，可保留五条总误差序列，但不传所有算法的完整高维内部状态。
- 两侧 `ErrorSeries` 的点数上限与 runner 的 `SERIES_CAP` 对齐；截断时必须显示。
- 初版不通过 Worker 回传逐子步完整姿态和 ESKF 矩阵；这些属于回看／诊断功能，不是对照摘要的必要载荷。
- 不在主线程长期保留无限多份对照历史。默认只保留当前结果，新结果完成时由用户选择是否替换。

## B.3 对照指标和导出

指标表至少包含：

- 当前观察算法的全程 RMSE、稳态 RMSE、最大误差、收敛时间；
- SO(3) 倾角／偏航 RMS（有真值时）；
- 观测接受率或拒绝数（该算法支持时）；
- 实际运行终点、最后解算时刻、pending tail；
- 精确／近似／early-stop 口径。

展示规则：

```text
Δ = B − A
Δ 为负且指标是误差：可说“本指标下降”
未收敛：显示“未收敛”，差值显示“不可比较”
样本为空：显示“无样本”
非有限值：显示“不可用”并保留诊断
```

报告使用独立类型，例如：

```ts
{
  schema: 1,
  kind: "quaternion-attitude-demo/comparison",
  restore: "results-read-only",
  createdAtIso: string,
  build: { commit: string, builtAt: string, buildId: string | null },
  baseConfig: ExperimentConfig,
  variable: ComparisonVariable,
  a: { config: ExperimentConfig, metrics: EstimatorRunMetrics[], termination: RunTermination },
  b: { ... },
  coverage: { seriesRetained: boolean, notes: string[] }
}
```

导入初版只需“查看报告”或不支持导入；不得将其交给 `parseArchive()` 当作可恢复实时配置。若支持“从报告复现”，应从明确选择的 A 或 B 提取配置，经档案同等校验后启动新实验，不恢复已保存曲线。

## B.4 学习活动与预测记录

```ts
type PredictionAnswer =
  | { kind: "single"; choiceId: string }
  | { kind: "multiple"; choiceIds: string[] }
  | { kind: "range"; min: number | null; max: number | null; unit: string };

interface LearningActivity {
  id: string;
  version: number;
  title: string;
  prompt: string;
  conditionsText: string;
  answerKind: PredictionAnswer["kind"];
  choices?: Array<{ id: string; text: string }>;
  evidence: {
    kind: "live" | "comparison";
    experimentId?: string;
    comparisonId?: string;
    estimatorId: EstimatorId;
    metric: string;
  };
  explanation: string;
  doc: { page: string; anchor?: string };
}

interface ActivityAttempt {
  attemptId: number;
  activityId: string;
  activityVersion: number;
  prediction: PredictionAnswer;
  predictionText: string;
  status: "predicted" | "running" | "ready" | "failed" | "cancelled";
  runRef: { kind: "live" | "comparison"; id: number } | null;
  reflection: string;
}
```

活动定义中的“合理预测区间”属于教学判断，不伪装成数值精确判分。预测与结果的关系可分为：

- 符合观察到的趋势；
- 与观察到的趋势相反；
- 无法由当前证据判断。

不能仅凭最终 RMSE 推断用户“理解了原理”。

### 活动状态机

```text
idle
  → answering
  → predicted（预测已锁定）
  → running（保存 runRef）
  → ready（结果与当前 activity/runRef 匹配）
  → reviewing（用户写反思，可重开新 attempt）

running → cancelled / failed
任何旧结果 → 不得推进当前 attempt
```

若允许“先自由预览再预测”，预览应清掉旧结果或标为预测前观察，并明确这会影响练习性质。默认建议先预测再显示结论，但不要禁止用户操作装置。

## B.5 分轴与可观性 DTO

```ts
type ObservationState =
  | "not-applicable"       // 算法本来不使用此通道
  | "disabled"             // 配置关闭
  | "invalid"              // 退化／模长异常
  | "rejected"             // 有效但被门控拒绝
  | "accepted-not-applied" // 接受但本步没有实际更新（若真实存在）
  | "applied";             // 本步实际应用

interface ObservationExplanation {
  channel: "accel" | "mag";
  state: ObservationState;
  reasonCode: string | null;
  evidence: {
    accelNorm?: number;
    angleDeg?: number;
    nis?: number;
    threshold?: number;
  };
  explanationKey: string;
}
```

`accepted-not-applied` 只有在生产语义确实存在时使用，不为凑齐状态而制造它。纯积分始终是 `not-applicable`，不是 `disabled/rejected`。

对于互补滤波这类直接姿态修正／插值的算法，是否“applied”必须按真实更新语义定义；如果每帧都进行某种融合，即使权重为 0，也应由估计器明确报告，而不是 UI 猜。

分轴数值使用有符号／无符号口径要分开：

- SO(3) `tiltDeg/yawDeg` 是误差**幅值**，默认非负；
- 若需要展示误差方向，另存旋转向量分量，不把幅值加正负号；
- 世界重力轴固定 `[0,0,1]`，从 `q_truth ⊗ q_est⁻¹` 分解；
- 外部真值存在时可用相同数学，但 UI 标“相对外部参考”；无真值时返回 `null`，不是 0。

## B.6 事件契约

```ts
interface LearningEvent {
  runId: number;
  seq: number;
  t: number;
  kind: string;
  estimator: EstimatorId | "all" | null;
  phase: "instant" | "start" | "end";
  summary: string;
  before?: unknown;
  after?: unknown;
  source: "solve-loop" | "sensor" | "transport" | "user-action";
}
```

要求：

- `seq` 在一轮内单调递增，用于同一时间多事件的稳定排序；
- 持续状态用 start/end，瞬时动作用 instant；
- `t` 来自生产数据／仿真时间，用户操作可额外存 `wallAtMs`，但不能替代 t；
- 未发生解算时的操作使用当前 `state.simTime`，不伪造未来解算时刻；
- `before/after` 只存可序列化的最小必要证据，不存 DOM、类实例或可变数组引用；
- `summary` 可由结构化字段渲染，避免导出语言与 UI 不一致；
- 门控事件按每个估计器分别归并，不将五算法状态混成一个全局拒绝状态；
- 事件列表保留“开始未结束”的状态，取消／重置时明确封存，不自动补一个假结束。

## B.7 回看帧与时间语义

```ts
interface ReviewFrame {
  runId: number;
  seq: number;
  t: number;                    // 本子步／记录点的数据时间
  truth: { kind: ReferenceKind; q: Quat | null };
  estimate: { id: EstimatorId; q: Quat };
  input: {
    raw: ImuSample;
    consumed: { gyro: V3; accel: V3; mag: V3 };
  };
  telemetry: EstimatorTelemetry;
  errors: { totalDeg: number | null; tiltDeg: number | null; yawDeg: number | null };
  eskf: KalmanStepSnapshot | null;
}
```

`truth.q=null` 时不能渲染真值幻影。`telemetry` 必须是在该 `t` 的更新之后复制，不能延迟到 25 Hz 记录时才复制已经属于后续解算的状态。

### 采样规则

- 以解算子步为源头，按记录预算决定“保留／跳过”；保留帧的时间仍为原始 `ctx.t`。
- 不用实时 rAF 时间替代数据时间。
- 曲线 25 Hz 和回看记录可以共用时间网格，但不得为了对齐网格而改写真实样本时间。
- 若选择最近帧，显示 `选中 t` 与 `实际帧 t`；若超过容差，允许查看曲线值，但不启用 3D 回看。
- 四元数记录需保持归一化和符号原值；不要为视觉平滑私自做 q 符号翻转后再当作诊断原始值导出。
- 传感器 `times` 若存在必须复制；不存在表示透传快路径，不补成当前时间。

### 回看状态机

```text
live
  → review（记录 return 所需的显示上下文，不改实时状态）
  → review-step / review-event
  → live（显示最新生产状态）

live/review → reset/source-change/import
  → 当前回看作废，旧帧不再可写当前视图
```

如果实时正在播放，后台仍推进生产状态；但 `state.simTime`、曲线追加和记录逻辑保持原行为。回看只改变展示。若实现上选择“回看时自动暂停”，必须明示并恢复原播放状态，不能暗中改变实验条件；推荐保留实时推进并清晰标识。

## B.8 ESKF 诊断快照

```ts
interface KalmanObservationSnapshot {
  channel: "accel" | "mag";
  available: boolean;
  predicted: V3 | null;
  measured: V3 | null;
  innovation: V3 | null;
  innovationAngleDeg: number | null;
  nis: number | null;
  gate: { kind: string; threshold: number | null; accepted: boolean; reason: string };
  S: number[] | null;
  K: number[] | null;
  dx: number[] | null;
  applied: boolean;
  qBefore: Quat;
  qAfter: Quat;
  biasBeforeRad: V3;
  biasAfterRad: V3;
  pDiagBefore: number[];
  pDiagAfter: number[];
}

interface KalmanStepSnapshot {
  t: number;
  dt: number;
  qInput: Quat;
  biasInputRad: V3;
  pDiagInput: number[];
  correctedGyroRad: V3;
  qPredicted: Quat;
  pDiagPredicted: number[];
  observations: KalmanObservationSnapshot[];
  qFinal: Quat;
  biasFinalRad: V3;
  pDiagFinal: number[];
  covarianceResetApplied: boolean;
}
```

初版只保存 P 的对角线用于分步解释；只有用户明确展开完整矩阵时才在记录中附带完整 P，且不能通过读取 UI 显示值来还原。若教学步骤必须展示完整前后矩阵，按需保存 36 个数值并计入容量。

### 采集不变量

1. `qInput/biasInputRad/pDiagInput` 在任何修改之前复制。
2. 预测段完成后记录 `qPredicted/pDiagPredicted`。
3. 重力观测完成后记录一次，磁观测按生产顺序再记录一次。
4. `applied=false` 时 `dx` 可以记录“计算了但未应用”的候选，或按设计为 `null`；文案必须区分，不得暗示姿态已改。
5. `qAfter/biasAfterRad` 包含真实限幅后的值。
6. 最终 `covarianceResetApplied` 与实际配置和调用一致。
7. 所有数组从生产值复制，快照被 UI 修改也不能影响估计器。
8. 采集器为空时，不分配诊断对象；采集器有异常时不得吞掉生产更新异常或改变控制流。
9. 快照只用于观察，不作为任何估计器下一帧的输入。
10. 数值等价测试比较 q、零偏、P、遥测、事件、指标和完整结果，不只比较最终姿态。

# 附录 C：界面布局与交互细节

## C.1 不增加首屏遮挡

首屏新增内容遵循：

- 不使用自动弹出的欢迎模态；
- 三入口可以是一张可收起的轻量卡片，或现有“引导课程”区的扩展；
- 主视图、播放／暂停、单步、重置、视图切换仍立即可达；
- 当前任务条可收起，收起后仍有“当前任务”的可恢复入口；
- 对照结果可放入右侧独立分区或底部可展开区，不覆盖 3D 模型；
- ESKF 解剖、完整矩阵和事件明细均为按需展开；
- 320/390 宽度下任务条只显示必要文字，完整证据靠展开而不是横向滚动整页。

## C.2 对照台的空／进行／失败状态

必须分别实现：

| 状态 | 界面 |
|---|---|
| 未创建 | 说明“固定配置与种子，只改变一个变量” |
| 配置中 | A/B 值、固定条件、配置 diff、运行按钮 |
| A 运行 | 当前侧、仿真进度、取消按钮，不清空已有无关实验 |
| B 运行 | A 的摘要可见，B 进度可见，不显示最终差值 |
| 完成 | 双侧曲线、指标、事件入口、导出与应用选项 |
| 取消 | 明示完成侧数，允许重开；不标完成 |
| 错误 | 哪一侧、什么错误、是否可重试；不清除当前实时装置 |
| 结果已过期 | 新配置／新任务已替代，旧结果仍可查看但不能冒充当前 |

## C.3 参数反馈的细节

- 连续 `input` 事件只在控件旁更新轻量值，不为每个像素触发 toast；
- `change` 或短暂停顿后聚合为一次任务反馈；
- 数值输入失焦／Enter 与滑块 change 使用同一最终值；
- 若请求值被量化到合法网格，显示“请求 5 → 实际 4”等真实关系；
- 触发重置时先完成既有生产动作，再报告实际行为；不能仅根据元数据声称成功；
- 元数据的 `resets` 用于解释，实际调用次数由浏览器测试核对；
- 切换数据源、导入档案等批量行为显示聚合摘要，避免几十条提示；
- 当前任务偏离只改变学习状态，不能锁住用户参数。

## C.4 事件与曲线

- 图形轨道仅作定位辅助，必有等价事件列表；
- 同一时刻多事件按 seq 稳定排序，可展开分组；
- 选择事件后保持类别过滤与滚动位置；
- 点击曲线空白处清除事件选中，但不必清游标；
- 鼠标离开曲线不清除已锁定回看；只有悬停查看才可清除；
- 左右方向键的移动粒度应与记录频率一致；原 0.04 s 曲线步进可保留，回看时采用相邻真实帧；
- 窗口裁剪后，不将游标悄悄移到另一时刻；提示“该事件已超出保留窗口”。

## C.5 ESKF 解剖的显示层级

```text
一级：本步总结——预测了什么，接受了哪些观测，最终改变了多少
二级：七个阶段卡片——每步一个关键数字／向量
三级：观测详情——S/K/dx 与单位
四级：完整矩阵与坐标系说明
```

不要用红绿颜色单独表达接受／拒绝；同时使用文字和图标／线型。所有数值能复制或选中，完整公式继续走现有公式复制路径。

## C.6 文档返回

- 文档链接打开前保存页面、章节、滚动位置和实际触发元素；
- 运行现场后关闭文档，焦点落到新任务标题或说明，而不是任意滑块；
- “返回阅读位置”重新打开相同文档，恢复页内位置，焦点回到原结论按钮；
- 若原按钮因教材版本／页面状态不存在，退回到对应章节标题并说明；
- 嵌套打开多个文档入口不形成无限返回栈；每个学习任务只保存一个来源位置；
- 直接打开文档而无任务来源时，保留现有“返回文档按钮”行为。

# 附录 D：跨功能状态、异常与资源管理

## D.1 各世代号不能混用

项目已有连接 generation、批量 generation、solveRunId 等机制。新增功能应明确使用哪一种：

| 对象 | 推荐身份 | 作用 |
|---|---|---|
| 实时实验轮次 | `solveRunId` 或统一复用其来源 | 曲线、回看、事件、消费快照隔离 |
| 对照计算 | `comparisonJobId + generation` | 取消、新旧结果、Worker 降级隔离 |
| 学习尝试 | `activityId + attemptId + runRef` | 预测与结果绑定 |
| 文档来源 | `taskId + doc location` | 阅读位置和焦点恢复 |
| 真实连接 | 既有 connection/session 机制 | 不新增第二套连接所有权 |

禁止把对照 jobId 当 solveRunId，也禁止只凭活动标题判断结果是否属于当前题。

## D.2 冲突处理矩阵

| 用户动作 | 对照运行 | 预测活动 | 回看 | 实时装置 |
|---|---|---|---|---|
| 修改参数 | 已完成结果保留并标非当前 | 当前活动标条件已偏离 | 旧帧保留原 runId，不混当前 | 按现有规则继续／重置 |
| 重置 | 不自动取消离线对照，界面标来源 | 若依赖实时证据，需重新运行 | 当前回看退出 | 原重置行为 |
| 切换数据源 | 模拟对照可查看但不可冒充真实结果 | 真值依赖活动明确不可用 | 旧回看退出或封存 | 按现有互斥规则 |
| 导入档案 | 旧对照不自动应用 | 条件偏离 | 旧回看退出 | 走 prepare/commit 事务 |
| 启动新对照 | 取消／替代旧任务 | 新 runRef | 不直接影响实时回看 | 不自动应用 A/B |
| 打开文档 | 计算可继续 | 状态保留 | 状态保留 | 现有播放行为 |
| 关闭页面 | 全部释放 | 不承诺持久化 | 缓冲释放 | 现有清理 |

这张矩阵是实现时的默认规则；若选择“重置自动取消对照”等更强行为，必须让用户可见并测试，不能发生静默后台任务。

## D.3 异常与缺失数据

必须区分：

- 尚未运行；
- 正在运行；
- 用户取消；
- runner 正常结束但无样本；
- 提前终止／early-stop；
- 结果过期；
- 计算失败；
- 真值不存在；
- 内部量未记录；
- 数据超出保留窗口；
- 该算法不支持此指标。

每一种都有明确文案，不统一显示“—”后让用户猜。日志与导出中不使用 JSON 无法区分的 NaN/null 混淆；导出 DTO 中非有限值转为明确的 `null + reason` 或字符串状态。

## D.4 性能预算

每项新功能都要回答：

1. 默认未开启时增加了多少每帧工作和内存？
2. 开启后每秒分配多少对象、保存多少数值？
3. Worker 一次回传多少字节，是否造成长任务？
4. 取消发生在哪个分片，最迟何时停止？
5. 高频状态是否合并渲染，是否每帧重建整块 innerHTML？
6. 文档不可见、回看未开启、ESKF 未选中时能否跳过工作？
7. 离开功能后监听器、定时器、Worker 和快照是否释放？

对照曲线和 ESKF 快照优先使用结构化、定长、可复用缓冲；若初版采用普通对象，必须实测并给出转为定长结构的阈值，不以“JavaScript 会 GC”为唯一保证。

## D.5 可访问性与教学等价文本

- 对照图提供表格／文本摘要，说明固定条件、变量和差值；
- 事件轨道提供可遍历列表；
- 3D 回看提供当前姿态四元数、姿态角和真值参考的文字版本；
- ESKF 每步提供文字结论，不只给矩阵；
- 状态更新使用合适的 `role=status`，避免 25 Hz 反复打断读屏；
- 进度变化按有意义阶段报告，不逐点朗读；
- 预测输入有 label、错误描述与焦点管理；
- 颜色之外还有标签、线型或符号；
- 新增按钮进入既有可访问名、对比度、键盘、窄屏和打印检查。

# 附录 E：分阶段任务卡与停止条件

## E.1 阶段 A 的可交付任务卡

### A1 配置变量契约

**输入**：现有 `ExperimentConfig`、五类变量。  
**输出**：类型化变量、构造 A/B、差异检查、验证错误。  
**完成**：合法／非法／原型路径／校准／种子／单位反例全部通过。  
**停止条件**：若现有 UI 无法无损读回某变量所需配置，先修配置读回，不用近似配置继续。

### A2 对照 runner 与 Worker

**输入**：合法对照请求。  
**输出**：A/B 双侧真实详细运行、进度、取消、错误。  
**完成**：与独立 runner 对拍、主线程降级和过期消息反例通过。  
**停止条件**：若曲线回传引发明显长任务或资源回退，先缩结果范围并记录，不把长任务留到 UI 阶段再处理。

### A3 对照视图与报告

**输入**：统一结果 DTO。  
**输出**：配置、运行、完成、失败、取消状态和报告导出。  
**完成**：指标口径、交换、未收敛、缺失数据与真实按钮路径通过。  
**停止条件**：不能清楚说明 B−A 和真值来源时，不显示“改善”等结论词。

### A4 参数元数据与任务条

**输入**：真实控件事件与任务定义。  
**输出**：变化反馈、影响层、重置说明、任务偏离。  
**完成**：用户／程序路径、量化、聚合提示、真实模式和窄屏测试通过。  
**停止条件**：元数据与实际重置行为不一致时，修真实契约，不靠文案掩盖。

### A5 阶段验收与冻结

保存变更摘要、测试清单、实际浏览器证据、性能／体积前后数字和未完成边界。若需要后续阶段才能完成的项，明确标“不在 A 范围”，不要把它们写成 A 已通过。

## E.2 阶段 B 的可交付任务卡

### B1 五道题内容评审

每题先提交内容卡：场景、预测类型、合理答案、实测证据、常见错误、解释、文档入口。数值区间由 runner 实测决定，不凭印象写死。

### B2 预测与结果状态机

实现提交、锁定、运行绑定、失败、取消、重新挑战、历史预测。先纯函数测试，再接 DOM。

### B3 结果解释与导出

显示预测／证据／解释；反思纯文本；导出包含活动版本和真实证据。无真实运行不导出“已验证”。

### B4 教材 claim 与导航

只选证据完整的结论添加按钮，建立 ID／锚点静态检查和文档焦点回归。

### B5 完整学习走查

至少执行：

- 一道答对趋势的题目；
- 一道错误直觉被实测反驳的题目；
- 一道先取消再重新运行的题目；
- 一次文档往返；
- 一次窄屏和纯键盘操作。

## E.3 阶段 C 的可交付任务卡

### C1 分轴数值与参考身份

先完成纯偏航、纯倾角、倾斜、锁点和无真值反例，确认坐标系和符号。

### C2 观测实际状态

逐算法定义 `not-applicable/disabled/invalid/rejected/applied`，在真实 update 后采样。对无法统一的算法显式缩减展示，不强行统一成假话。

### C3 事件归并

先粗对准和观测边沿，再饱和、断流与参数操作；每种事件有唯一生产来源和 seq。

### C4 时间轴与证据展示

图形、列表、过滤、键盘、容量、过期状态和文档解释完整联动。

### C5 与已有实验整合

至少让“方向门控救场”“磁干扰与偏航”“陀螺仪量程饱和”“初始对准”四类实验能使用新证据；不扩展到隐藏故障诊断。

## E.4 阶段 D 的可交付任务卡

### D1 回看容量原型

先测 25 Hz×30 s 的帧数据量、分配、渲染与回放开销，确定是否保留全部五算法姿态或仅当前算法。教学需要切换算法时，再评估多算法快照。

### D2 只读回看

实现真实帧缓冲、游标、场景展示、返回实时和跨轮隔离。未通过“回看无副作用”前不接 ESKF 大快照。

### D3 ESKF 生产采集

先写采集开关逐位等价测试，再插桩预测、观测和注入。若需要重构 update 才能安全采集，保留同一运算顺序，禁止“顺手优化”矩阵运算。

### D4 ESKF 解释视图

从单步摘要到矩阵分层显示，覆盖接受、拒绝、双观测、限幅、奇异和重置。

### D5 资源与发布证据

对回看开／关、ESKF 开／关分别测量内存与性能，并跑长稳。默认关闭路径不应承担高成本快照分配。

## E.5 阶段 E 的完成定义

不仅“所有功能能打开”，还要完成：

- 任务状态冲突矩阵的真实浏览器验证；
- 所有入口和出口的键盘与焦点；
- 新增文本和数值的教学内容复核；
- 现有能力的完整回归；
- 性能、体积、长稳、视觉、读屏和证据绑定；
- README 双语与应用内教材更新；
- 方案中“未来”措辞改为真实实施状态，未做项继续明示；
- 当前源码／产物／量具身份与验收报告一致。

## G.4 不能由模型自封完成的结论

以下结论即使全部代码和测试都通过，也必须保留人工边界或明确标为未测：

1. **「教学有效」**：模型能证明题目可运行、答案正确、界面可用，但不能证明学习者因此学会了。学习效果需要真实用户或教师评估。
2. **「数值预测区间合理」**：区间太宽失去练习意义，太窄制造挫败感。模型可用 runner 实测，但「合理」是教学判断，需人工确认。
3. **「读屏体验良好」**：ARIA、焦点陷阱和自动化检查是必要条件，不是充分条件。真实 Narrator／NVDA 的听读节奏、冗余度和理解负担必须由人验证。
4. **「视觉无问题」**：模型可以独立查看截图并给出模型视觉评审，但这不等于真人最终验收。若项目要求人工视觉判定，模型评审不能替代。
5. **「产品语义正确」**：例如「回看时是否自动暂停实时」「是否允许用户修改参数后仍保留原任务」等，属于产品决策，模型不应擅自决定。
6. **「可以发布」**：合并、推送、部署、发布 Release 和线上核验需要明确授权，不属于模型自主范围。

## G.5 模型可以自主签署的结论

在代码、测试、浏览器回归和性能实测全部通过的前提下，模型可以自主签署：

- 配置契约与数值一致性；
- 异步生命周期（取消、过期、隔离）；
- 生产来源正确性（事件、遥测、快照）；
- 内存与体积的实测边界；
- 自动化浏览器路径与回归；
- 文档与代码的一致性；
- 模型视觉评审（明确标注为模型评审，不冒充真人）。

## G.6 建议的最低人工复核清单

若项目所有者希望用最少的人工时间获得最大收益，建议按优先级只复核以下五项：

1. **F-02 的 5 道预测题**（教学合理性与数值区间）；
2. **F-03 的可观性文案**（领域准确性）；
3. **F-07 的 ESKF 解释**（领域准确性）；
4. **真实读屏走查**（Narrator／NVDA，15～30 分钟）；
5. **对外发布与线上核验**（授权与最终确认）。

其余全部可由模型自主完成并留下可复核的自动化证据。
