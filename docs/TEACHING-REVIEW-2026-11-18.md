## 4. 已确认有效的修复

### 4.1 固定教学基线

`run()` 从 `teachingBaseConfig()` 构造，不读取现场配置。固定种子、初态、校准状态和完整 IMU 参数，活动 patch 再施加目标条件。

独立探针确认的固定题：

- 漂移题：`pure.max = 19.830005933450877°`，符合 15–25° 范围；
- 延迟题：`pure.max = 6.015469218379962°`，符合 4–8° 范围；
- 非题目现场噪声、带宽、初态、校准或 A/B 不再影响固定练习的实际路径。

此前的 19.83→9.31 和 6.02→13.29 的污染反例不再用于当前生产运行，因为当前 `run()` 不读取现场。

### 4.2 倾角修正的因果证据

当前 yaw 题分为 A/B/C：

- A：30° 倾角偏差，正常 Mahony 修正；
- B：同倾角，Kp=Ki=0，无修正负对照；
- C：纯偏航 30°，关闭磁修正。

独立生产结果：

```text
A tiltRmse = 6.698618837°
B tiltRmse = 30°
Δ = 23.301381163°（门槛 ≥20°）
C yawRmse = 30.000154348°
C tiltRmse ≈ 0.007658585°
```

判据使用 A 相对 B 的倾角下降，不是“倾角本来就小”。这修复了上一轮没有初始倾角却声称纠错的证据缺口。

### 4.3 Ki 窗口效果

当前 A/B 两侧只有 Mahony Ki 不同，固定磁开启、零噪声和 20 秒窗口：

```text
A：Ki=0，steadyRmse = 2.630400909°
B：Ki=0.05，steadyRmse = 1.279485208°
Δ = 1.350915701°（要求 ≥0.5°）
```

可支持“当前固定条件下，20 秒内稳态误差明显下降”。完整题目的其余分支仍未被覆盖，见 TQ-11。

### 4.4 门控 claim 基线

claim 现在会先装载 `gate` 实验，设置 A 侧门控关闭，再冻结并创建 `accel-gate` 对照。实测有 `violent` 与 `linAccel=4`，开侧产生真实拒绝事件，已经不再是默认 hover 的零拒绝空对照。

这一修复证明入口和生产条件已接通，但仍需验证教材最终结论，见 TQ-12。

### 4.5 历史回看与 ESKF 同源

当前服务已有：

- 快照缺失明确提示，不回退实时或邻帧；

## 5. 体积专项：为什么当前不能继续堆功能

### 5.1 当前实测与预算含义

| 项目 | 实测 / 有效门槛 | 结论 |
|---|---|---|
| 全部 JS gzip | **299,514 / 299,520 B** | **仅余 6 B** |
| 总产物 | 约 2027.5 KiB / 2029.5 KiB | 余约 2.0 KiB |
| 教学按需 chunk | 约 114.0 KiB / 129.6 KiB | 余约 15.6 KiB，不能抵消 JS 总闸 |
| 诊断 chunk | 约 48.4 KiB / 57.6 KiB | 余约 9.2 KiB，同样不能抵消总闸 |

注意：分类块余量不能转移给全部 JS 或总产物。6 B 余量意味着下一次看似很小的正确性修改也可能超线。

此前文档出现 1.4 KiB 总量余量、另一些文档性能数字与报告不一致的现象；不能拿这些不一致的数字做预算决策。

### 5.2 推荐优先级

#### P1：先修归因，再合并与去重，**不抬门槛**

**归因优先于减重。** `size-report.mjs` 当前将多个 lazy chunk 归成 `main`，且漏计 `sw.js`，还会因构建是否生成 sourcemap 产生行尾差异。应修复扫描、分类和总和对账，使：

```text
所有 chunk 的 gzip 之和（含 sw.js）== 全部 JS gzip
```

再执行以下实验：

1. 评估合并 `comparison-ui + teaching-ui + diagnostics-ui`；
2. 去除真实重复的 JSON 深拷贝、说明格式化、单位／标签／结构代码；
3. 评估 `main.ts` 中真正无需首屏的工具，避免把首屏工作迁移到 lazy chunk；
4. 对每一步保存 before/after 的 raw/gzip、首屏行为、输入延迟和取消时序；
5. 检查按需模块导入是否把 UI 反向拖进 Worker，或把默认路径变成预加载。

**至少恢复 2 KiB 工作余量，建议 2–4 KiB。** 不需要为凑回旧的 244.8 KiB 目标而删教学功能。

#### P2：合并 lazy chunk 的实测入口

当前对三个已 minified 的 chunk 直接合并压缩的结果：

```text
分别压缩合计：57,886 B
合并后压缩：56,314 B
估算节省：1,572 B
```

这只是对当前已生成代码的压缩对照，不是一次完整 Vite 构建结果。它说明**合并有收益但不足以单独解决长期演进空间**，所以仍要做去重。

合并后必须验证：

- 只打开诊断／学习／对照时是否出现不应有的下载或初始化；
- 冷加载反馈是否仍及时；
- 对照启动、取消、主线程降级和旧世代不回写；
- 回看游标、历史 Inspector、教材返回和既有短路径；
- 原始、压缩后的实际 gzip 与总量；
- Worker 不能反向 import 全部教学 UI。

若合并增加不必要的预加载或初始化，不能只为了预算保留该合并。

#### P3：去重对象建议

优先查找而不是猜测：

- `event-timeline` 与 `review-buffer` 中 JSON 深拷贝职责；
- 观测说明和格式化中的重复文本／结构；
- `observability` 对当前遥测显式状态的完整覆盖与兼容回退的真实需求；
- 共享数字／单位／标签／算法名称的生成代码。

不得删除“无数据时不补 0”“无快照明确缺失”“旧输入拒绝”这些必要的语义分支。兼容性回退如果确有历史快照／旧遥测输入，应明确保留其真实调用路径，而不是用仅测试用例来证明还需要。

#### P4：停止并报告，不要自行抬线

如果按上述方法后仍不足 2 KiB：

```text
停止新增功能
保留已验证的正确性修复
报告：当前字节、模块归因、已尝试动作、剩余缺口、性能前后对照
由项目所有者决定：是否只提高全部 JS 上限，或调整范围/结构
```

总量目前也不宽裕，不能先抬总量以解决全部 JS 的问题。旧 P2 授权不是无限次提高上限的通行证。如果确实要抬全部 JS，必须记录新旧门槛、归因、用户价值和后续禁止增长范围；不能只改一个数就宣称减重。

2. 长期趋零及适用条件作为理论解释，说明不是当前窗口结论；

5. 题面声称的玻璃盒积分修正量，要么实际纳入证据，要么删去未实现的观察要求；
6. 区分 Mahony 积分项和 ESKF 的零偏状态。

**永久反例：**

- [ ] Ki=0.05 确有显著窗口改善；

- [ ] 无振荡证据时，题目不能声称已经实测振荡；

### 10.3 资源与回收（TR-05）

### 10.4 本轮发现并修复的真实缺陷

换源（sim → replay → sim）会在 `selectedQ()` / `sourceLabel()` / `sourceColor()` / 闭环反馈处对 `ests.find(...)` 的结果直接取属性。回放会重建估计器集合，此刻 `state.source` 可能指向已不存在的算法，于是抛 `TypeError` 并**打断仿真步**（表现为「仿真步异常，已暂停」）。

修复：新增 `sourceEstimator()`，四处调用点全部改为「找到就用，找不到回退第一个可用算法（再无则回退真实姿态）」。修复后换源循环控制台零错误。
