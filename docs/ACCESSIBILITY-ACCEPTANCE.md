# 可访问性与窄屏阅读验收记录（SW-11）

> 这份记录回答的是「**哪些格子真的验过、哪些没验**」，而不是「全部通过」。
> 每个格子写清：机制（怎么测的）、证据（哪个用例/报告）、结论，以及**未测项与原因**。
> 自动化的部分都由 `npm run check` / `npm run smoke` 强制执行；人工与工具不支持的部分显式标未测。

## 0. 本次验收的环境与口径

| 项 | 值 |
|---|---|
| 平台 | Windows（本机工作站；本阶段只支持 Windows） |
| 浏览器 | Edge / Chrome 真实进程，headless `new` + swiftshader 软件渲染 |
| 视口 | 320×568 / 390×844 / 768×1024 / 1440×900（另加 720×450 @DPR2 的页面缩放用例） |
| 代码 | `npm run smoke`（107 项，含 4 条 SW-11 用例）与 `npm run perf` 的报告都在本机跑出并随仓库版本化 |

## 1. 验收矩阵

| 场景 | 必须核对 | 机制与证据 | 结论 |
|---|---|---|---|
| 320 / 390 / 768 / 1440 | 主界面与文档无丢失内容；表格内部滚动可操作；**导航不长期占满首屏** | 冒烟「窄屏（390）：文档目录默认收起、首屏即见正文、可键盘展开」+「窄屏布局无横向溢出」+ 视觉证据 4 档视口截图 | **通过**：390 px 下目录默认收起（导航高 135 px，正文 top 180 px < 844 px 视口）；展开后列表封顶 45% 视口高；320 px 桌面外壳由视觉证据覆盖 |
| 页面缩放 200% | 面板重排、图表与提示无遮挡、关键按钮可达 | 冒烟「页面缩放 200%（CSS 视口 720×450 @DPR2）：提示条不遮挡读数且无横向溢出」 | **通过**：读数条 11 条全部未被遮挡，横向无溢出（720/720） |
| 纯文字放大 200% | 文字真实变大后仍不截断、不压住输入与读数 | 冒烟「纯文字放大（根字号 200%）」：改**根字号**观察排版 | **实测为"不生效"**：本装置版式以 px 计量，浏览器「字体大小」设置不改变排版（读数条字号 11.5→11.5 px），放大后布局不破、无截断。**未测**：真实浏览器「字体大小」设置的用户路径（headless 无法驱动该设置）、字体放大后的人工视觉确认 |
| 键盘 | 焦点顺序、对话框语义、读数等价文本与状态反馈可用 | 冒烟「纯键盘往返」（Enter 打开 / Tab 30 次不跑出对话框 / Shift+Tab 回卷 / Esc 关闭并归还焦点）+「交互控件都有可访问名，且无正向 tabindex」 | **通过**：焦点陷阱有效、关闭后焦点回到「文档」按钮；全部交互控件有可访问名 |
| 键盘（文档模块目录） | 折叠目录可键盘开合 | 冒烟「窄屏目录」用真实 Enter 键开合 `<summary>`（`<details>` 原生支持键盘与展开状态） | **通过** |
| 读屏 | 标签、图表等价文本、状态提示频率 | — | **未测**：本机没有可自动化的读屏软件（NVDA/Narrator 需人工操作）。已做的准备：对话框 `role="dialog"`+`aria-modal`、目录 `<details>/<summary>` 原生语义、状态行文案由 `ui/batch-table.ts` 纯函数统一生成 |
| 文档 / 打印 / 导出弹窗 | 实际内容清晰、打印仅输出目标分页、弹窗错误可恢复 | 冒烟「打印媒体」「导出弹窗（含勾选范围一致性/错误恢复）」+ 视觉证据 print 两张截图 | **通过**（自动化部分）；**人工视觉判定未做**：截图采集成功不等于人工看过，见第 3 节 |
| 对比度 | 文字对比度达 WCAG AA | 冒烟「全站文字对比度达 WCAG AA（含低对比度负对照必须被抓到），逐页确认扫到全部文档页」 | **通过**：15/15 文档页扫描，注入的负对照被抓到 |
| 长标题 / 遮挡 / 截字 | 视觉检查遮挡、截字、焦点可见性 | 冒烟遮挡检测（提示条 vs 读数条）+ 「文字被截断」检测 | 部分覆盖：**仅对已列出的元素**做了矩形相交与 `scrollWidth>clientWidth` 检测；「长标题截断」未做整站扫描 |

## 2. 已知限制与建议（不粉饰）

1. **纯文字放大不生效**：版式以 px 计量。等价的用户需求应由**页面缩放**满足（已测），但「把系统字体调大」这一路径确实无效。
   如果要改成可用，需要把正文与读数排版改成 `rem` 并重新验证遮挡——这是一次**大范围版式改动**，本轮未做，
   记为待办而不是"已支持"。
2. **读屏与人工视觉判定未做**：没有可自动化的读屏环境；截图的"采集成功"与"视觉通过"分开记录，
   不得用前者代替后者（见第 3 节）。
3. **窄屏只验到 390 / 320**：更窄（<320）与横屏矮视口（如 640×360）未验。

## 3. 「采集成功」与「视觉判定」分开记录

- **采集成功**：`npm run evidence:visual` 产出 11 张截图（4 档视口 + 200% 缩放 + 三视图 + 文档 + 打印两张），
  报告 `docs/generated/visual-evidence.json` 记录视口、字节数、sha256 与源码/产物摘要；
  像素哈希由 `scripts/evidencecheck.mjs` 逐张复核。
- **视觉判定**：由人（或独立的视觉评审）看图后给出，**不属于**自动化结论。本记录不声称已完成人工视觉判定。

## 4. 复现方式

```bash
npm run build && npm run preview     # 另开一个终端
npm run smoke                        # 107 项：含窄屏、页面缩放、纯文字放大、键盘往返、对比度、可访问名
npm run perf                         # 页面性能：输入延迟 p95、墙钟帧率、长任务、内存峰值
npm run evidence:visual              # 11 张截图 + 版本化报告（PNG 在 screenshots/，被 gitignore）
```
