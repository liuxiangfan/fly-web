# 可访问性与窄屏阅读验收记录（SW-11）

> 这份记录回答的是「**哪些格子真的验过、哪些没验**」，而不是「全部通过」。
> 每个格子写清：机制（怎么测的）、证据（哪个用例/报告）、结论，以及**未测项与原因**。
> 自动化的部分都由 `npm run check` / `npm run smoke` 强制执行；人工与工具不支持的部分显式标未测。

## 0. 本次验收的环境与口径

| 项 | 值 |

| 平台 | Windows（本机工作站；本阶段只支持 Windows） |
| 浏览器 | Edge / Chrome 真实进程，headless `new` + swiftshader 软件渲染 |

## 2. 已知限制与建议（不粉饰）

1. **界面文字已支持三档，但不等于“浏览器字体设置已验证”**：style.css 已全量 rem 化（基准 14px，档位 14/17/20 px，换算 `rem = 原 px / 14`），界面档位由应用内下拉控制并经浏览器冒烟验证；**Canvas 图表内文字由 JS 绘制，不随档位缩放**。headless 仍无法驱动真实浏览器「字体大小」设置，该用户路径与放大后的人工视觉确认**未测**，不得写成已验证。
2. **读屏范围外、视觉由所有者确认**：项目所有者 2026-11-17 明确不需要读屏功能；视觉截图由所有者人工确认“功能都正常、没有问题”。截图的"采集成功"与"视觉判定"仍分开记录（见第 3 节）。
3. **窄屏只验到 390 / 320**：更窄（<320）与横屏矮视口（如 640×360）未验。

## 3. 「采集成功」与「视觉判定」分开记录

- **采集成功**：`npm run evidence:visual` 产出 11 张截图（4 档视口 + 200% 缩放 + 三视图 + 文档 + 打印两张），
  报告 `docs/generated/visual-evidence.json` 记录视口、字节数、sha256 与源码/产物摘要；
  像素哈希由 `scripts/evidencecheck.mjs` 逐张复核。
- **界面文字档位截图**：2026-11-20 在 4173 真实预览采集标准/大/特大三张桌面图与一张 320px 特大图，位于 `D:/test-artifacts/quaternion-attitude/visual/stage5-font/`；根字号实测 14/17/20 px，320px 大/特大均为 `scrollWidth=innerWidth=320`，控制台 0 错误。模型已查看特大桌面与 320px 图，未见空白画布或横向溢出；这不是所有者逐图验收，也不代替真实读屏。
- **视觉判定**：项目所有者 2026-11-17 表示“功能都正常、没有问题”，记录为当时的所有者功能确认；不扩大为他们逐张核对了后续构建截图。第四次冻结采集的 11 张 PNG 已在后续图像输入中用 Read **实际逐张查看**：桌面、320/390/768、200% 缩放、三视图、文档及打印未见意外重叠、横向溢出或空白画布，控制台 0。保留早期同会话 `selected model does not support image input` 的过程记录，但不把它继续当作当前视觉缺口。这是模型视觉检查，不是所有者逐图验收，也不代替读屏。
- **读屏**：项目所有者 2026-11-17 明确不需要该功能，本阶段标为范围外，不以自动化检查冒充真实读屏。

## 4. 复现方式

```bash
npm run build && npm run preview     # 另开一个终端
npm run smoke                        # 126 项完整清单（app 105 + devices 21）：含界面文字档位、窄屏、页面缩放、键盘往返、对比度、可访问名
npm run perf                         # 页面性能：输入延迟 p95、墙钟帧率、长任务、内存峰值
npm run evidence:visual              # 11 张截图 + 版本化报告（PNG 在 screenshots/，被 gitignore）
```
