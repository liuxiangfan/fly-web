## P1 · 已确认的实质缺陷

### 1. 磁校准模型切换的状态迁移需要补强（**不作为已确认的核心算法缺陷**）

`magCalFit()` 会按 `magcal-model` 选择模型；自动采集会重新生成样本、清空旧校准并重新拟合。因此不能把「自动采集必然使用旧模型」列为已确认缺陷。真正需要补的是：模型切换时旧校准/样本如何失效、结果是否明确显示当前应用模型，以及防止用户以为只改下拉就会重新标定。

**处理**：模型切换明确提示是否清除旧校准并重新拟合；显示「选择模型」与「实际应用模型」；增加完整↔对角切换及自动采集的端到端用例，断言 `MagCalibration.kind` 与实际输入，不只断言拟合成功。

### 2. A/B 的 B 组没有真正冻结参数

`applyAccelGate`、`applyMagMode`、`applyKalmanGate`、`kalman-reset-cov` 同时修改 A 与 `abState.clones`。分叉后修改 A 的门控/磁形态/卡尔曼配置也会改变 B，所谓「参数快照、单变量对比」不成立。

**处理**：拆分 A/B 参数应用；B 的配置在快照时冻结，后续只读；增加「分叉后修改 A 的每个设置，B 的配置完全不变」测试。

### 3. A/B 的静止粗对准只重置 A 组

`stepStillness()` 只重置 `ests`，不处理 `abState.clones`。触发粗对准后，A/B 的姿态、bias、P、积分器与启动年龄逐渐失去配对关系。

**处理**：统一 A/B 的对准事件和内部状态；增加「分叉后触发静止对准」回归用例。

### 4. 实验档案是「配置复现」，不是「当前实验精确还原」

`buildArchive()` 固定 `currentExperimentConfig(30)`，不包含当前时刻、噪声流位置、估计器运行状态、当前 A/B 时刻和原始记录。导入会从零起跑，不能回到当前曲线。

**处理**：明确拆成「配置档案」与「运行快照」两类；前者只承诺 seed 起跑，后者保存 World/估计器/随机流/时间/记录状态。先修正文案和 UI 的过度承诺，再决定是否实现运行快照。

### 5. 运动学一致剧本下闭环开关实际无效

`World.step()` 在 kinematic 分支直接写死姿态，不使用 `feedbackQ`，所以闭环不会把估计误差带回轨迹。

**处理**：运动学剧本下禁用闭环并解释，或把闭环改成真正参与平动/姿态跟踪的控制器；不得继续把它描述为全场景通用能力。

### 6. 带外部真值回放仍禁用「真实姿态」来源

探针确认：完整 `truth_q*` 回放中 `hasGroundTruth()` 为 true，但 `source-select` 的 `truth` 选项仍禁用；`real-mode-note` 也仍写「无真值、Mahony 基准」，与 external reference 不一致。

**处理**：按 `hasGroundTruth()` 启用 truth 来源；读 `state.externalTruth`；同步提示、图例、导出标签；增加完整真值列回放的端到端用例，而不只测无真值 CSV。

## P2 · 运行内核与界面语义不一致

### 7. 批量 runner 没有完整复现界面辅助状态机

runner 复用 World/IMU/估计器，但未覆盖界面的静止对准、A/B、INS、闭环等全部逻辑；B 配置与部分卡尔曼设置也可能不同步。

**处理**：抽出共享 `SimulationSession`，让 UI 和 runner 使用同一调度；用 golden trace 比较同 seed 下 runner/UI 的逐帧序列，覆盖粗对准、A/B、门控、校准、闭环、低解算频率。

### 8. 批量统计窗口和定义不够严谨

- 没有分开启动暂态与稳态；
- `maxTiltRmse/maxYawRmse` 是多个 seed 中最大的单次 RMS，不是跨种子均值或 P95；
- 总误差 <2° 的收敛定义可能在正常初值时立即满足；
- UI 无论选择 10 s 还是 30 s 都写「单次 30 s 内是否达到 <2°」。

**处理**：显示全程与稳态 RMSE 两列；稳态用后半段或可配置窗口；用跨种子均值/P50/P95；收敛要求持续保持；文案使用实际 durText。

### 9. A/B 快照的 same-start 不是「历史不变」

same-start 会 `resetSim()`，两组从零起跑，适合参数对比但不是从当前历史分叉。online-fork 虽复制状态，却仍受 A 后续配置修改和静止对准影响。

**处理**：same-start 保持现状并准确命名；online-fork 统一冻结语义；用状态字段快照比较分叉前后所有配置和运行状态。

## P2 · 物理与校准模型的边界

### 10. 传感器时间模型仍是离散近似

仍缺传感器独立时间戳、真实采样率与解算率分离、非整数延迟插值/状态传播、完整圆锥/划船补偿。当前按历史帧取样本，不能等价为完整时间戳模型。

**处理**：每帧带 sampleTime；区分采样、滤波、打包、算法消费；非整数延迟用插值或状态传播；提供简化/完整模型对照，而不是把简单模型当物理事实。

### 11. 完整磁椭球的形状正确不等于方向正确

对称软铁测试方向误差可恢复到近 0，但非对称软铁仍有未知旋转残差，绝对场强依赖目标值；目前主要用拟合数据自身评估，独立验证集不足，真机验证不足。

**处理**：拟合集/验证集分开；增加真实噪声、部分姿态覆盖、不同软硬铁组合与外部航向参考；将「点云成球、方向可恢复、场强已知」列为三项独立指标；真机结果单独报告。

### 12. 六面校准静止判据只看平均角速度

0.5 s 平均角速度 <3°/s 可能掩盖正负摆动抵消、短时晃动、加速度模长变化。

**处理**：同时检查最大角速度、方差、加速度模长变化；按每段静置而非整窗平均判断；提供逐段不稳定反馈。

### 13. 批量与长跑的内存/性能管理仍有限

MetricAccumulator 保存每个 seed 每种算法的全部误差数组，批量结果还保留所有 runs；分片让出主线程不等于低内存。15 s/40 s 长跑不足以覆盖完整批量负载。

**处理**：在线累计 sum/sumSq/max，分位数用有界 reservoir 或分桶；批量只保留汇总；重计算迁移 Web Worker；评估完整批量的内存曲线和耗时。

## P2 · 文档与恢复锚点

`docs/PROJECT-STATE.md` 仍保留过时计数（实验库 17 个而非当前 19 个、文档演示 6 个而非当前 8 个 Canvas），架构表也未完整列出 online-fork、完整椭球、六面校准、传感器流水线与运动学场景；当前状态与历史里程碑混杂。

**处理**：顶部只保留当前真实状态，历史另移 `docs/CHANGELOG.md`；动态计数由脚本或结构检查生成；README 的「精确还原/完整复现」改为准确能力边界；增加文档与代码的事实检查。

## 测试盲区

### 1. 组合状态覆盖不足

缺少或未充分覆盖：

- 完整校准 → 切模型 → 重新采集；
- online-fork → 改 A 参数 → 观察 B；
- A/B → 静止粗对准；
- online-fork → reset → 改磁形态/门控；
- 回放外部真值 → 选择真实姿态来源；
- 运动学剧本 → 闭环；
- 导入档案 → 当前时刻/当前状态复现。

### 2. 部分断言偏宽松

- `hasNees` 只检查 `Number.isFinite`，未验证数值合理性和与 runner 一致性；
- 批量只查表格行数，不查与 Node runner 的数值一致；
- 六面校准 UI 主要通过调试注入样本，未验证真实按钮采集与静止判据；
- online-fork 只测初始分叉，不测分叉后的配置变化和自动对准；
- 缺真机 BLE/串口断线、重连、错误帧与长时间运行。

### 3. 测试辅助方式改变被测状态

部分测试直接 `classList.remove("collapsed")`，没有同步 `aria-expanded`，UI 与 ARIA 可能不一致。

**处理**：优先点击真实按钮；用真实文件输入/真实回调替代部分 `window.attitudeDemo` 注入；增加属性/ARIA 同步断言；区分核心逻辑测试与用户行为测试。
